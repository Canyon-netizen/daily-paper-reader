## What shipped this iteration

### 1. Multi-dimensional library inclusion standard (the foundation)

**Doc:** [`docs/library/inclusion-standard.md`](library/inclusion-standard.md)
**Code:** [`astro-src/lib/library/audience-profiles.ts`](../astro-src/lib/library/audience-profiles.ts)
**Types:** added `audienceProfile?: 'novice' | 'expert' | 'reviewer' | 'practitioner'` to `LibraryDefinition`

Four personas, each with:
- 5–7 weighted axes (sum to 1.0)
- Default threshold
- LLM prompt addendum (injected into scorePaperRelevance)
- Anti-patterns list

Threshold resolution order (new):
```
opts.threshold > library.definition.relevanceThreshold >
profile.defaultThreshold > 0.5
```

Verified by: `tests/test_library_audience_feedback.mjs` (11/11 pass).

### 2. User feedback collection system

**Code:** [`astro-src/lib/library/feedback.ts`](../astro-src/lib/library/feedback.ts)
**Events:** new `dpr:library-feedback` event in the 3-file ritual (names/types/bus)
**Doc:** [`docs/feedback/README.md`](feedback/README.md)
**Calibration log:** [`docs/feedback/library-inclusion-log.md`](feedback/library-inclusion-log.md)

11 event kinds (library_created/deleted/profile_changed/threshold_changed/
paper_included/excluded/marked_irrelevant/candidate_score_too_low/too_high/
paper_reading_status_changed/feedback_note).

Storage: `localStorage['dpr_library_feedback_v1']`, FIFO 5000 entries, no PII.

**Wired into:**
- `user-libraries/store.ts:createLibrary` → logs `library_created`
- `user-libraries/store.ts:updateLibraryDefinition` → logs `library_profile_changed` + `library_threshold_changed`
- `user-libraries/store.ts:bulkSetPaperStatus` → logs `paper_included` / `paper_excluded` (with `relevanceScore` + `audienceProfile` snapshot)

3. **PhD journey map — should each phase have a separate /onboarding/phase-N/ page in the live site?** Currently docs-only.
4. **The 5 research-skills primers — should they live as in-app /help/ pages or stay as docs?** The latter is faster to ship.
