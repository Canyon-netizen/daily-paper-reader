## 摘要
在未来的决策系统中，AI智能体有望发挥日益重要的作用。在本文中，我们考虑由异构多智能体系统（MAS）组成的协作系统，其中各成员具有不同的能力与运行成本。我们研究智能体如何在资源受限的场景下相互委托任务，从而有效地完成某些研究任务。我们首先开发了一种基于多智能体强化学习（MARL）的委托训练方法，使智能体能够做出序贯委托决策，同时最小化总执行成本。然后，我们将该方法扩展到具有预设委托拓扑的MARL。此外，我们为多智能体系统中的协作与委托提出了两个新框架。第一个框架提出，智能体的策略不仅依赖于底层马尔可夫决策过程的当前状态，还依赖于交互历史，包括先前的联合动作。这种依赖于历史的表述方式即使在完全可观测的环境中也能改善协作，而传统的MARL方法通常将策略限制为仅依赖于当前状态。第二个框架提出了一种新颖的、潜在多维的货币机制，以促进多智能体系统中的协作与委托。

## Abstract
AI agents are expected to play an increasingly important role in future decision-making systems. In this paper, we consider collaborative systems composed of heterogeneous multi-agent systems (MAS), where their members have different capabilities and operating costs. We study how agents can delegate tasks to one another so that certain research tasks can be completed effectively under resource-constrained scenarios. We first develop a multi-agent reinforcement learning-based (MARL) delegation training that enables agents to make sequential delegation decisions while minimizing the total execution cost. We then extend this approach to MARL with prescribed delegation topologies. Furthermore, we introduce two new frameworks for collaboration and delegation in multi-agent systems. The first framework proposes that an agent's policy depends not only on the current state of the underlying Markov decision process but also on the interaction history, including previous joint actions. This history-dependent formulation can improve coordination even in fully observable environments, where conventional MARL methods typically restrict policies to depend only on the current state. The second framework proposes a novel, potentially multi-dimensional monetary mechanism to facilitate the collaboration and delegation for MAS.

## 2. 方法论

### 2.1 统一形式化：协作 Markov Game

设异构 $n$ 个 agent 的协作 MG：

$$M = \{N, S, A, P, R, \gamma, \{\mu_i\}_{i=1}^{n}, T, K\}$$

其中每个 agent $i$ 拥有**已预训练冻结**的任务策略 $\mu_i : S \times A_i \to [0,1]$；MARL 在它们之上学习一个**委派元策略** $\pi : S \times A \to [0,1]$，决定每步由谁执行。联合目标为：

$$J(\pi) = \mathbb{E}_{\pi, P}\!\left[\sum_{t=1}^{T} \gamma^{t-1} \sum_{i \in N} R_i(s_t, a_t)\right]$$

三类约束（由易到难）：
1. **Management constraints**：上–下级单向委托（如 $A \to B \to C$ 链），每步只允许一位执行；执行规则为
$$a_{exec} = \begin{cases} a_{\mu_A}, & a = (a_{\mu_A}, \cdot, \cdot)\\ a_{\mu_B}, & a = (d_{A\to B}, a_{\mu_B}, \cdot)\\ a_{\mu_C}, & a = (d_{A\to B}, d_{B\to C}, a_{\mu_C}) \end{cases}$$
2. **Delegation constraints**：完全图式委托，多 agent 可同时执行；agent 仅在被别人委托**且自己不外委**时执行。
3. **Money trading**：上述框架基础上引入可转移货币作为激励。

每个 agent 的单步奖励统一写作：

$$R_i(s, a) = \alpha \bar{R}(s, a_{exec}) - \beta C_i(a_i)$$

其中 $\bar{R}$ 为环境奖励，$C_i(a_i)$ 为个人执行/委派/不操作成本，$\alpha, \beta$ 为缩放因子。

### 2.2 历史依赖策略（History-dependent Policy）

- 定义**公共历史** $h_t = (x_1, a_1, x_2, a_2, \ldots, x_{t-1}, a_{t-1}, x_t)$。
- 策略映射为 $\pi_t^i : H_t \to A_i$（Markov 策略是其特例：$\pi_t^i(h_t) = \mu_t^i(x_t)$）。
- 历史依赖可表达**互惠回报 / 跨期激励**，论文用一个两阶段 toy game 证明：在 Markov 均衡下 A 的最大回报为 $9.0$，B 为 $5.0$；而在历史依赖均衡下存在 $(8.9, 6.0)$ 的帕累托改进，证明 Pareto 上界的提升。
- **算法 1：Two-step Nash Value Iteration**：枚举所有确定性历史依赖 continuation selector $\sigma_2$，为每个第一阶段动作生成 induced game，求其纯策略 Nash 均衡，最终选择最大化某指定 agent 价值的均衡配置。
- **定理 1**：在两步博弈的所有子博弈均存在纯策略 NE 假设下，算法 1 输出子博弈完美的纯策略 Nash 均衡。
- 通过对最后两步向后归纳，可扩展到有限 $n$ 步博弈。

### 2.3 多维货币机制（Money Transfer）

- 每个 agent $i$ 携带**货币余额状态** $w_t^i \geq 0$，扩展状态为 $\tilde{s}_t^i = (s_t, w_t^i)$。
- 在每步动作空间新增 $p_t^i = [p_t^{ij}]_{j \neq i} \in \mathbb{R}^{n-1}_+$ 的转账动作；合约 $Cr_i : A \to \mathbb{R}^{n-1}$ 把每个联合动作映射为固定支付列表。
- 全策略分解为 $(\pi_{env}^i, \pi_{tr}^i)$。
- 关键约束：若 $\lVert p_t^i \rVert_1 > w_t^i$，对应联合动作不可执行，需切换到"买得起的"动作；当 $w_t^i = 0$ 时不允许任何转账。
- 货币**独立于环境奖励**：$J(\pi)$ 仅最大化 $\sum R_i$，货币只承担"记录交互历史 + 激励委派"的内部功能，与 DRIVE / LIO 等把激励作为 reward-shaping 信号的 peer-incentivization 工作**根本不同**。

## 3. 实验设计

### 3.1 数据集与场景
- **Benchmark**：GSM8K（grade-school math word problems，Cobbe et al., 2021）。采用 main split 中 1000 条做离线能力映射（ability map）、6473 条训练、1319 条官方测试集 holdout。
- **冻结求解器栈**：
  - Solver A = Nemotron 3 Ultra（强且贵）
  - Solver B = Llama 3.2 3B Instruct
  - Solver C = Llama 3.2 1B Instruct
- **仅训练 central DQN 协调器 $\pi$**，A/B/C 在训练与评估期间保持冻结；离线一次性缓存各 solver 的回答与由 Ultra 做出的正确性标签，避免训练中重复调用 LLM 和 labeler，保证可复现。

### 3.2 任务设定
- 每个 episode 含 32 道题，每道题最多 3 次尝试（3 次全错则步奖励 $-1$）。
- 训练 1000 episodes，使用 $\gamma = 0.99$，成本权重 $\lambda = 100$，handoff 费率 $\alpha = 0.05$。
- 每个 solver 单独离线准确率（held-out dev bank）：Ultra ≈ 96.7%，Llama 3B ≈ 84.5%，Llama 1B ≈ 53.7%。
- Synthetic token 价格（$/1M 输入/输出）：Ultra $1.00 / $3.00；3B $0.25 / $1.50；1B $0.05 / $0.10。

### 3.3 对比方法
- **Management 实验**（3.1）：DQN+map / DQN no-map / **always-Ultra**（无 handoff 强 baseline）。
- **Delegation 实验**（3.2）：DQN+map / DQN no-map / always-Ultra / 冻结的 management 协调器（Mgmt. $\pi$，跨组"匹配数据包"对照）。
- **Money Transfer 实验**（3.3）：
  - 独立 Q-learning（IQL）：5000 episode 后 agent 全部学成 Null，环境回报恒为 0。
  - 增强型 IQL + 可转移货币：学成对称的全 Yes 合作策略，每个 episode（20 步）取得 $990$ 的环境回报。

### 3.4 显著性检验
所有 20 个 seed 上的配对 Wilcoxon signed-rank 检验：management 与 delegation 两组对比 always-Ultra，回报和成本差异在所有种子上一致，two-sided $p = 2^{-19}$。

## 4. 资源与算力

- **硬件**：NVIDIA **A100-SXM4-80GB** GPU；论文明确每个 seed 使用**单卡 A100**。
- **软件栈**：Linux + Python 3.10 + PyTorch 2.5.1（CUDA 12.1 wheels）、NumPy、Gymnasium、HuggingFace transformers。
- **离线标注**：Ultra 的离线正确性标注通过 API 完成，**不计入**协调器 $\pi$ 的步成本。
- **每次运行规模**：1000 episodes × 32 题；DQN 隐层 128，batch 32，replay buffer 80 000，target 网络每 200 步同步，$\varepsilon: 1 \to 0.05$（20 000 步衰减）。
- **未明确披露**：总训练时长（小时数）、总 GPU·小时数、API 标注 token 数；附录 D 仅记录了如上配置，未给出 wall-clock 时间。

---

## 5. 实验数量与充分性

- **种子数**：所有 GSM8K 实验均报告 **20 个独立 seed（0–19）** 的 mean ± std，进行配对 Wilcoxon 检验与图示跨种子的求解器调用比例。
- **场景覆盖**：三大框架各**单独跑一组**（management / delegation / money transfer），未做大规模消融：
  - 未对 GSM8K 之外 benchmark（如 MATH、RouterBench）做迁移验证；
  - 未对 $\alpha$、$\lambda$、handoff 费率做敏感性 sweep；
  - 未在更多 agent（$n > 3$）或非链式拓扑上验证可扩展性；
  - 历史依赖策略仅给出 toy 2-step game 与算法 1，**没有在更大 MARL 基准上实证**。
- **公平性**：always-Ultra 与 learned coordinator 在**相同 cache / cost 规则**下评估；management 协调器在 delegation 图环境中以匹配数据包重放，避免了 cache 偏差；用统一 DQN 配置且未做 per-method 调优（如实承认"未做大网格搜索"），这一点既减少了过拟合风险，也使得性能提升主要归因于结构而非超参。
- **可复现性**：离线缓存 + 固定 seeds + 详细附录 Listing 1/2，使数字可在没有实时 LLM 的环境下重现。

## 6. 主要结论与发现

- **历史依赖能扩展 Pareto 边界**：toy 2-step game 上，Markov NE 的 B 最大回报为 $5.0$，而历史依赖 NE 可达 $6.0$（A 同时从 $0/4.5/9.0$ 提升至 $8.9$）。
- **Management 框架**（GSM8K）：协调器回报 $27.56 \pm 0.32$，准确率 $0.982$，每集成本 $\$0.033$；always-Ultra 为 $23.90$ / $0.971$ / $\$0.063$。累计 1000 episodes 成本从 $\$60.8$ 降至 $\$31.1$（约 -49%），回报提升约 $+3.7$。
- **Delegation 框架**：协调器回报 $25.20 \pm 0.42$，每集成本 $\$0.043$；always-Ultra 为 $23.31$ / $\$0.068$。累计成本由 $\$66.7$ 降至 $\$45.5$（-32%）。同一数据包上冻结的 management 协调器表现更强（$28.70$ / $\$0.024$）。
- **求解器调用模式**：management 策略主要依赖 B、辅以 A，几乎不调用 C；delegation 策略更倾向调用 C，并出现多 agent 同题作答的情况，因此回报 / 准确率比 management 略低但成本也更低。
- **货币机制**：在两 agent 序列游戏中，IQL 自身收敛到全不合作（回报 0），引入 $w_t^i$ 余额与"按合约支付 1 单位"的转移后，5000 episode 后学成对全合作的 Yes 策略，每 episode 环境回报 $990$。
- **总体**：在保持或提升环境奖励/准确率的同时，MARL 协调器可显著降低 LLM 调用成本；历史依赖策略与可转移货币是支持完全协作均衡的有效机制。

---

## 7. 优点

- **统一的形式化**：把"是否执行 / 委派 / 不操作"建模为 agent 的内生动作，区别于把 routing 当成"中心化调度"的传统方法。
- **历史依赖 + 货币两条互补机制**：明确指出历史依赖在**完全可观测**环境下仍有意义（互惠激励），货币与环境奖励严格解耦，克服了 reward-shaping 类方法对任务奖励可分性的假设。
- **严格定理保证**：算法 1 + 定理 1 + n 步归纳扩展，给出子博弈完美纯策略 Nash 均衡的存在性 / 构造性结论，区别于纯实证式工作。
- **可复现实验设计**：离线缓存 + 固定 seeds + 详细附录 + DQN 无 per-method 调优，保证结果主要由方法结构而非超参搜索解释。
- **充足的统计检验**：20 seeds + 配对 Wilcoxon + 报告 mean ± std，使 +1.9 / +3.7 回报与成本差异不依赖单种子偶然性。

## 8. 不足与局限

- **实证规模有限**：
  - 仅在 GSM8K（单基准、英文小学数学）上验证，未在 MATH、HumanEval、RouterBench、LLMRouterBench 等更广泛的任务或 routing 基准上迁移。
  - 仅 $n=3$ 的小规模 agent 集，未扩展到 5–10 agent；未考察不同拓扑的 scalability。
  - 历史依赖策略的算法 1 仅在 toy 两步博弈上做了说明式演示，**没有在大规模 MARL 环境上实证其带来 Pareto 改进**。
- **货币机制的实证过度简化**：3.3 节的两 agent 实验是 2 步完全确定性 toy 环境，未涉及部分可观测、噪声 reward 或非完全信息博弈；初始资金、合约价格 $\in \{0, 1\}$ 二元化，难以推广到现实 API 计费场景。
- **超参与结构调优不足 / 也未做消融**：附录 D 明确"未跑大网格搜索"，因此对 $\alpha$、$\lambda$、handoff 链路设计是否鲁棒无敏感度分析；未消融历史依赖、货币机制二者分别的边际贡献。
- **求解器与角色偏差风险**：使用 Ultra 同时作为求解器 A **和** 离线正确性裁判（手检 200 题一致后整体沿用），可能引入系统性评分偏差（虽承认了这一点并指出可替换）；且只评估"派给谁"，并未让被指派的 agent 自行决定是否委派给下游，缺乏对 agent 自主拒绝行为的真实模拟。
- **可扩展性 / 工程缺口**：仅给出概念性 Listing 1/2，未提供完整脚本访问入口（仅指明在 supplementary ZIP），不便第三方复现。
- **算力与时间披露不全**：未报告 wall-clock training time、累计 GPU·小时或 API 标注成本。
- **未来工作**（作者自陈）：
  - 基于历史联合动作的**动态定价**尚未实现；
  - 历史依赖策略下求解 Nash / CCE 的**更高效算法**仍是开放问题；
  - 三类约束（management / delegation / money）目前分开验证，未在同一统一基准下综合比较。
