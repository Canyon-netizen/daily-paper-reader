## 摘要
基于大语言模型的多智能体系统与多智能体强化学习相结合的训练方法正迅速引起关注，一条并行的工作路线则主张，此类系统应当依据其行为而非仅依据奖励来评判。我们在空间合作博弈研究中同时推进这两条线索：在这些博弈中，使用底层动作提示的小型冻结大语言模型会彻底失败，奖励为零。

在选项/半马尔可夫决策过程（options/semi-MDP）框架的指导下——并且，由于各智能体间的选项执行是异步的，我们采用其在宏动作去中心化部分可观察马尔可夫决策过程（Dec-POMDP）中的多智能体扩展——我们为每个博弈配备一个符号\emph{选项}库：这些选项是带有类型标注、状态可行、面向短视野的行为，由符号规划器执行。每个选项库由一个前沿编码模型根据博弈源码起草；用于筛选每个选项菜单的可行性守卫，则由廉价的随机策略试运行回放机械合成——只有当某个守卫能够解释反复出现的执行失败，同时不会隐藏任何已记录的成功时，该守卫才会被采纳——因此没有任何守卫是经人工编写、挑选或通过奖励调优得到的。

每个智能体的大语言模型充当其关于选项的策略，并配备一个私有的逐智能体 LoRA 适配器，通过多智能体 GRPO 的一种逐智能体变体（PA-MAGRPO）训练得到；这一方法使冻结的基础模型在三个博弈和四个小型骨干网络上从零奖励跃升至胜任水平。

随后进行的行为审计揭示出奖励与合作之间存在脱钩：上升的奖励曲线可能仅仅意味着某个智能体学会了独自完成全部任务，而其合作伙伴则无所事事——只有当任务使合作成为必要时，合作才会涌现。因此，单凭奖励无法可靠地反映合作程度，行为评估必须与奖励评估并行进行。

## Abstract
Training LLM-based multi-agent systems with multi-agent reinforcement learning is rapidly gaining traction, and a parallel line of work argues that such systems should be judged by their behavior, not only their reward. We take up both threads in spatial cooperative games, where small frozen LLMs prompted with low-level actions fail outright, earning zero reward. Guided by the options/semi-MDP framework---and, because option execution is asynchronous across agents, its multi-agent extension in macro-action Dec-POMDPs---we equip each game with a library of symbolic \emph{options}: typed, state-feasible, short-horizon behaviors executed by a symbolic planner. Each library is drafted by a frontier coding model from the game's source code; the feasibility guards that filter each menu are then synthesized mechanically from cheap random-policy burn-in rollouts---a guard is adopted only if it explains repeated execution failures while hiding no logged success---so no guard is authored, selected, or reward-tuned by hand. Each agent's LLM acts as its policy over options, with a private per-agent LoRA adapter trained by a per-agent variant of multi-agent GRPO (PA-MAGRPO); this lifts frozen bases from zero reward to competent play across three games and four small backbones. Behavioral audits then reveal that reward and cooperation decouple: a rising reward curve may simply mean that one agent has learned to run the entire task alone while its partner idles---cooperation emerges only when the task makes it necessary. Reward alone is thus an unreliable readout of cooperation; behavioral evaluation must sit alongside it.

# 论文总结：Training Small LLMs as Spatial Multi-Agent Policies

## 1. 核心问题与研究动机

**问题定义**：在 2D 空间合作博弈中，将小型（2–4B 参数）冻结大语言模型（LLM）直接提示输出底层动作（如方向键、交互键）会完全失败——奖励始终为零。这暴露了三大障碍：

- **接地鸿沟（grounding gap）**：小模型无法将高层目标（如"清理北方的 dirt"）可靠地映射为底层原语动作，出现空间前置条件幻觉与"安全默认动作"模式崩塌。
- **视野问题（horizon problem）**：单局博弈步数数百、奖励稀疏，决策步上的信用信号几乎为零。
- **专门化问题（specialization problem）**：合作常常要求智能体扮演不同角色，但若共用同一组权重，冲突的角色梯度会被平均化，团队坍缩为相同行为。

**研究目标**：在学术预算下把小型 LLM 训练为空间合作 MARL 策略，并系统回答"训练成功后真正涌现了什么"。

## 2. 方法论

### 2.1 整体框架：两阶段耦合

- **决策层抽象**：把每个智能体的动作空间从原语提升为固定**符号选项（symbolic options）库**；每个智能体在决策点收到一个按状态过滤后的字母菜单（lettered menu），仅选择"做什么"，由符号规划器决定"怎么做"。
- **训练层专门化**：在共享冻结底座上为每个智能体挂一个私有 LoRA 适配器，用 **PA-MAGRPO**（per-agent MAGRPO）独立更新。

### 2.2 形式化建模

底层为协同部分可观察随机博弈（Dec-POMDP）$(\mathcal{S}, \{O_i\}_{i=1}^N, \{A_i\}_{i=1}^N, \Omega, P, R, \gamma)$。每个选项 $z = \langle I_z, \pi_z, \beta_z \rangle$ 对应：启动集 $I_z$（哪些观测下可被选中）、内部策略 $\pi_z$（符号规划器展开为原语）、终止条件 $\beta_z$（完成、失败或超时）。由于各智能体异步终止，团队层面问题为**宏动作 Dec-POMDP**（macro-action Dec-POMDP）。智能体 $i$ 在观测 $o_t^i$ 下的可行动作集合记为：

$$Z_i(o_t^i) = \{ z \in \mathcal{Z}_i : o_t^i \in I_z \}$$

策略 $\pi_i(z \mid o_t^i)$ 仅支撑于该菜单，决策只在选项边界发生，从而形成半马尔可夫决策过程（semi-MDP）。

### 2.3 符号选项库的构建流水线（共 4 阶段，前沿模型仅参与 1 次）

- **Stage 1（仅一次前沿模型调用）**：用 Claude Opus 4.8 阅读博弈源码，输出带"四部分契约"（实例化、执行器、终止、效果谓词）的类型化选项库。执行器被刻意保持"环境天真"，仅检查目标存在、可达路径、是否持有物品等算法内在前置条件，**不编码任何环境合法性策略**。
- **Stage 2（uniform-over-menu burn-in）**：用均匀随机策略在每个候选菜单上跑试运行（Overcooked AA 上约 2 000 solo + 2 000 双智能体 episode，约 550 k 决策，70 秒/单核 CPU 即可完成），记录每个选项执行的 `success` / `effect_fail` / `explicit:<reason>` 三类标签。
- **Stage 3（guard 合成与接受证书）**：
  - *显式通道*：观察到 ≥ 5 次的具名失败原因直接转为守卫。
  - *推断通道*：对读取集合的所有 1-/2-文字合取打分，仅当 $\text{support}_{\text{fail}} \geq 5$ 且 $\text{support}_{\text{succ}} = 0$ 时采纳（"零成功隐藏"证书）。
- **Stage 4（菜单组装）**：每个选项按目标类逐实例化（而非仅最近目标），逐实例应用守卫；字母用 episode-seeded RNG 每步重排，避免模型对字母位置产生先验偏置。
- **外层契约修复回路**：当燃烧日志或证书出现可疑模式（如某选项显式失败率 100% 但任务仍可达），由前沿模型改契约，重新跑 Stages 2–3。论文列出 3 类实际遇到并修复的缺陷：绝对形式效果谓词、共享状态归因错误、最近目标实例化。

### 2.4 PA-MAGRPO 训练算法

每个 round 收集 $K$ 条联合 rollout，使用共享团队回报 $R_k$ 做组内归一化得到共享优势：

$$\hat{A}_{k,t} = \frac{R_k - \mu}{\sigma}, \quad \mu = \frac{1}{K}\sum_k R_k,\ \sigma = \mathrm{std}_k R_k$$

每个智能体 $i$ 在自身决策序列 $\{(o_{k,t}^i, z_{k,t}^i)\}$ 上做 $E$ 个 PPO 裁剪 epoch，仅更新其私有 LoRA $\theta_i$：

$$L_i(\theta_i) = -\mathbb{E}\!\left[\min\!\big(\rho_{k,t}^i\hat{A}_{k,t},\ \mathrm{clip}(\rho_{k,t}^i, 1-\epsilon, 1+\epsilon)\hat{A}_{k,t}\big) + \beta\,\mathrm{KL}\!\left(\pi_{\theta_i}^i \,\|\, \pi_{\mathrm{ref}}^i\right)\right]$$

其中 $\rho_{k,t}^i = \pi_{\theta_i}^i(z_{k,t}^i \mid o_{k,t}^i) / \pi_{\theta_i^{\mathrm{old}}}^i(z_{k,t}^i \mid o_{k,t}^i)$。优势对所有智能体相同，专门化通过"相同优势下不同观测–动作历史"在私有参数中沉淀。

| Overcooked-AI **Forced Coordination (FC)** | 2 | 400 | 双方互相依赖，必须 counter hand-off |
| **Commons Harvest** | 7 | 400 | 公共池资源，过度采摘会导致 patch 永久消亡 |

AA / FC 组成"博弈内对照"，区分可选协调 vs 必需协调。

### 3.2 模型骨干

跨骨干稳健性实验使用 **4 个小型骨干**：Qwen3-4B-Instruct-2507、Qwen3.5-2B、gemma-4-E4B-it、gemma-4-E2B-it。消融实验固定 Qwen3-4B 底座。

### 3.3 对比方法

6 个消融单元，枚举 `抽象 ∈ {option menu, compound-JSON, native actions}` × `能力 ∈ {per-agent LoRA, shared LoRA, no training}`：

- **Full method (ours)**：option menu + per-agent LoRA + MAGRPO
- **Abl. A**：native 原语 + MAGRPO（去抽象）
- **Abl. B**：option menu + 共享 LoRA + MAGRPO（去专门化）
- **Abl. C**：frozen + native（不训练）
- **Abl. D**：compound-JSON + per-agent LoRA + MAGRPO（去菜单过滤）
- 附加行：Frozen + option menu（无训练，仅菜单）

### 3.4 评估协议

- 主表每个 cell 为 20 个评估 episode，使用固定测试种子集 $\{10000,\ldots,10019\}$。
- 跨骨干表每个 cell 跑 5 个独立训练种子（含选项库采样、LoRA 初始化、rollout 随机性、minibatch 顺序四个通道）。
- 行为审计：per-agent 宏动作直方图、访问热力图、patch 生存曲线、solo/partner 对照测试。

### 3.5 基准结果速览

- **跨骨干表**：所有 frozen baseline = 0；full method 在 Cleanup 上达 $60.25\!-\!105.69$ 个苹果，Overcooked AA $6.21\!-\!7.31$ 次配送，Commons Harvest $85.41\!-\!115.52$ 个苹果。
- **消融表**：Qwen3-4B 上 full method 在 Cleanup 由 $0.00 \to 93.25$，Overcooked AA 由 $0.20 \to 6.80$（约 34× 提升）；Abl. A/Abl. D 在 Overcooked 上训练全程崩溃于 0；Abl. B 共享 LoRA 在 Cleanup 最佳仅 $0.10\pm0.45$。

## 4. 资源与算力

- **训练硬件**：单卡 H100（"Training runs on a single H100"）。
- **Stage 2–4（guard 合成）**：仅使用 CPU，Overcooked AA 上 4 000 episode（≈ 550 k 决策）约 70 秒单核。
- **超参**：Cleanup / Harvest 用 LoRA rank 32、lr $5\times10^{-5}$、$K=4$、温度 0.7；Overcooked 用 LoRA rank 16、lr $2\times10^{-5}$、$K=6$、温度 0.9、KL 系数 0.05。统一 $\epsilon=0.2$、2 inner epochs、梯度裁剪 1.0。
- **训练种子数**：跨骨干 5 个/骨干；消融 1 个 seed。**论文未给出 wall-clock 训练时长**，仅说明 checkpoint 选取规则与评估 episode 数。

## 5. 实验数量与充分性

- **总训练运行数**：4 骨干 × 5 seed = 20 次（Table 1），消融 6 cell × 1 seed（Table 2），合计 ≥ 26 次端到端训练。
- **统计显著性**：主表报告均值 ± 标准差及 95% 百分位置信区间（10 000 重采样），与 frozen baseline 的逐对 Mann–Whitney U 检验 $p<10^{-7}$。
- **充分性评估**：
  - 既有跨骨干稳健性，又有跨博弈行为审计，并以"同一固定配方"贯穿，避免 cherry-pick。
  - 通过 Forced Coordination 与 solo-test 等**博弈内对照**机制，缓解奖励欺骗（reward hacking）带来的偏差。
  - 缺点：消融 suite 仅 1 seed，置信区间仅反映评估侧波动；行为模式（如 Cleanup 角色分配）只在 1 seed 上验证；论文明确承认这一点。

## 6. 主要结论与发现

1. **配方有效**：option menu + per-agent LoRA + PA-MAGRPO 在 4 骨干 × 3 博弈上把 frozen 底座从 0 奖励拉到有竞争力水平；任一组件移除都会导致关键游戏上训练崩溃（Abl. A、C）或能力塌缩（Abl. B）。
2. **决策步压缩**：菜单使 LLM 调用比从 1.00 降至 0.40–0.71，每步决策跨 2–3 个环境步，压缩信用分配视野。
3. **奖励与合作脱钩（双向）**：
   - *高奖励 ≠ 合作*：Overcooked AA 上 agent 0 约 69% 决策在装洋葱，agent 1 约 72% 在等待，counter 操作 0%，呈现"一工一闲"；单飞测试两个 agent 都还能交付。
   - *低/平奖励 ≠ 无合作*：Commons Harvest 上 apple 奖励曲线几乎平（$76.73 \to 98.29$），但 patch 生存数从约 0 跃至约 2.5/6 持续到 400 步，体现约 2 个 agent 节制、其余等待的可持续策略。
   - *必要才合作*：Forced Coordination 下 frozen = 0、trained = $7.57\pm1.16$，且 solo 测试都失败——只在此布局下才出现真正涌现的协调。
4. **自发角色分工**：Cleanup 上 7 个 adapter 无角色标签地自发分化为 3 eater / 3 cleaner / 1 静态 helper，并由访问热图空间对应（果树 vs 河岸）。共享 LoRA 与 compound-JSON 都无法重现这一分化。

---

## 7. 优点

- **机械合成守卫而非人工编写**：guard 来自燃烧日志的统计模式（"解释失败且隐藏零成功"），不接触奖励、不接触人类，规避策略泄漏与奖励黑客。
- **抽象与学习两层解耦**：抽象层（options + guards）由一次性前沿模型 + 固定算法生成，训练层只更新策略；Stage 1 之后前沿模型不再被查询，保证 compute / 一致性。
- **per-agent LoRA 是轻量专门化方案**：在冻结底座上保留通用语言与任务知识，仅为差异化留出参数空间；明显优于全量微调的算力代价。
- **"同一配方 + 行为审计"的方法学贡献**：把奖励曲线与社交结果指标（效率、平等、可持续性、hand-off 等）并置，揭示了 reward 单读数的不可靠性。
- **轨迹级诊断完备**：直接给出 LLM 调用的"动作分布崩塌"原始 trace，让 ablation 结论可验证。
- **跨骨干 / 跨博弈稳健性**：结果不依赖单一 backbone，且 AA/FC 这一博弈内对照设计具备说服力。

---

## 8. 不足与局限

- **规模与任务范围受限**：仅覆盖 ≤ 4B 的小型 LLM 和 3 个空间合作博弈；向更大模型或非空间任务的可迁移性未验证。
- **选项空间选择缺乏原则**：option 库按博弈定制，由前沿模型一次性起草，目前没有系统化的选项空间设计准则。
- **统计样本偏小**：消融 suite 仅 1 训练种子，置信区间只反映评估侧波动；行为层面的角色分配只在 1 seed 上检查。
- **行为审计本身是经验性证据**：作者明确指出"the decoupling finding is behavioral evidence, not a general theory"；跨任务可重复性有待更多实验。
- **单 GPU 预算下可扩展性未知**：单 H100 的训练时长未报告，更大规模或更多智能体的扩展成本与可行性不明。
- **潜在偏差来源**：训练种子同时控制选项库采样、LoRA 初始化、rollout 随机性、优化顺序——单一交互作用难以完全剥离；不同骨干在 Cleanup 上的标准差（最大达 50.71）说明接口与初始化的影响仍显著。
- **语言模型在 zero-shot 阶段的极端失败**：2–4B 冻结底座在 3 个游戏上全 0 奖励，这一"对照基线"较为温和——可能在更大模型或更强 prompting 下不成立，使方法相对优势的普适性受限。
