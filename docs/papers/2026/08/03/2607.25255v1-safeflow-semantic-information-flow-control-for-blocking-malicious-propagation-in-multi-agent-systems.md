## TL;DR

SafeFlow 针对多智能体系统中恶意目标通过任务分解绕过单轮检测这一安全盲区，提出了将跨智能体恶意传播建模为语义信息流问题的防御思路。该框架通过为根请求附加结构化语义污点、沿动态协作图传播并在动作执行前进行全局风险验证，在涵盖提示注入、不安全工具使用、风险代码执行和有害 Web 智能体行为的四个基准测试中显著降低了攻击成功率，同时保持了较高的良性任务完成率。

## 研究背景与动机

多智能体系统近年来在复杂任务处理上展现出显著优势，其核心机制——任务分解与角色专业化——使得系统能够通过将庞大目标拆分为可管理的子任务来提升整体能力。然而，这种设计哲学在带来效率提升的同时，也悄然引入了一个尚未被充分重视的安全盲区：恶意意图可以被精心包装成一系列在单个智能体看来完全合理、无可疑之处的局部子任务，从而在每个环节都成功规避检测。

这种攻击模式的危害性在于它对多智能体架构的适应性。当攻击者设计一个有害目标时，他们不需要在单个提示或单轮交互中完成全部恶意操作，而是将其分散到不同智能体的职责范围内。例如，一个旨在窃取敏感信息的攻击可能包含多个步骤：某些步骤看起来像是常规的数据查询，另一些步骤像是正常的文件处理，还有一些步骤像是标准的通信协议。这些步骤单独审视时都不存在明显风险，但组合起来却构成了完整的数据泄露路径。

传统安全机制在此类攻击面前显得力不从心。基于单轮提示分类的检测方法只能在单个智能体的视野内进行风险评估，它们无法获知一个看似无害的子任务在整个工作流中的真实角色——它究竟是正常业务流程的一部分，还是某个恶意大图中的关键拼图。这种视角的局限性使得即使每个智能体都严格把关，最终仍然可能让恶意意图得逞。

论文的核心洞察在于：这种失败模式本质上是一个信息流问题，而非单纯的分类问题。恶意信息（语义层面的“有毒”内容）沿着智能体之间的协作关系流动，逐步接近敏感资源或关键操作节点，而检测机制需要追踪这种跨边界的信息传递才能有效拦截。认识到这一点，研究者决定将防御思路从“单点检测”转向“全局信息流控制”，这构成了 SafeFlow 框架的出发点。

## 方法

SafeFlow 的设计围绕一个核心观察：要在多智能体系统中有效阻断恶意传播，安全机制必须具备跨委托边界追踪语义风险的能力。具体而言，该框架将语义污染标记附加到根请求上，使这些标记能够随着智能体间的协作自动传播，并在关键节点进行全局验证，从而重建被任务分解所割裂的完整风险上下文。

整个框架的运作可以概括为三个相互关联的阶段。在标记附加阶段，系统为进入工作流的根请求生成结构化的语义污点。这些污点不仅包含简单的“危险/安全”二元标签，而是携带了关于恶意意图性质的更丰富信息：攻击类型、预期危害后果、受影响的数据或资源类别等。这种结构化设计使得污点在后续传播过程中能够被更精确地处理和解释，而不仅仅是作为一个模糊的警告信号。

接下来的传播阶段是框架的核心创新所在。SafeFlow 构建了一个动态协作图来建模智能体之间的交互关系，这个图随着工作流执行而动态演化。每当一个智能体将任务委托给另一个智能体时，附加在原始请求上的语义污点也会沿着这条委托关系同步传递。这种传播机制确保了即使恶意目标被分解为数十个子任务，污点信息也会如影随形地跟踪着整个执行链路，而不会因为任务拆分而丢失。

关键的设计考量在于传播的时机与条件。SafeFlow 并不对每个子任务都执行严格的污点检查——这样做会带来难以承受的性能开销。相反，它采用了一种基于风险累积的策略：当污点累积到一定程度，或者工作流即将执行不可逆的高风险操作时，框架才会触发全局验证。这种设计在安全性和效率之间取得了平衡，使得框架能够在保持较低性能开销的同时捕获关键风险节点。

在验证阶段，SafeFlow 会在动作执行前进行工作流级别的全局风险评估。这个评估重新组装被分散到各个子任务中的完整信息，通过分析污点的当前分布、目标智能体的历史行为模式、以及当前操作的潜在后果，综合判断是否存在恶意传播的风险。如果检测到高风险意图，框架可以选择拒绝执行、请求人工确认、或对操作进行安全化改造（例如对输出进行脱敏处理）。

值得强调的是，这种验证机制解决了任务分解所带来的语义割裂问题。单个智能体在进行本地决策时，只能看到自己负责的子任务，无法了解该任务在全局工作流中的上下文意义。而 SafeFlow 的全局验证通过汇聚所有相关智能体的局部信息，重建了一个完整的风险图景，使得原本隐藏在大局中的恶意意图无处遁形。

## 实验与结果

研究者设计了四个覆盖不同攻击场景的基准测试来评估 SafeFlow 的有效性：提示注入攻击、不安全工具使用的越狱尝试、风险代码执行场景、以及有害 Web 智能体行为。每个基准都模拟了恶意攻击者利用多智能体系统的任务分解机制来逐步推进恶意目标的真实威胁模式。

实验采用攻击成功率作为主要评价指标，同时关注良性任务完成率以确保安全机制不会过度干扰正常功能。研究团队将 SafeFlow 与无防御基线以及多种外部防御方法进行对比，覆盖了从简单规则匹配到基于大型语言模型分类器的多种技术路线。

实验结果清晰地表明，SafeFlow 在所有四个基准测试中都显著降低了攻击成功率。相比无防御基线，SafeFlow 将攻击成功率降低了相当大的幅度，优于大多数外部防御方法。这一结果验证了语义信息流控制思路在处理跨智能体恶意传播问题上的有效性。

更值得注意的是 SafeFlow 对良性任务完成率的保持。多智能体安全领域的一个常见陷阱是安全机制过于保守，导致大量正常任务被错误拦截。SafeFlow 通过精细的污点管理和条件触发的验证策略，成功避免了这一困境。实验数据显示，使用 SafeFlow 的系统在大多数任务类型上保持了与无防御基线相当的良性任务完成率，说明安全增强并未以牺牲功能为代价。

研究者还引入了一个名为“配对安全—危害成功率”的复合指标来更全面地评估框架性能。这个指标衡量的是系统在成功拒绝恶意请求的同时，能够正确放行对应良性请求的能力。SafeFlow 在这个指标上同样表现优异，进一步证实了其在精确度和召回率之间的良好平衡。

消融实验揭示了框架各组件的贡献程度。移除语义污点的结构化信息（简化为二元标签）会导致性能下降，说明污点的丰富语义表示对于准确风险评估至关重要。同样，如果没有动态协作图的传播机制，仅依靠静态规则进行检测，也无法有效捕获跨智能体的复杂攻击模式。这些结果为 SafeFlow 的设计选择提供了实证支持。

## 讨论与可借鉴点

SafeFlow 的研究揭示了多智能体系统安全领域一个根本性的设计缺口：现有系统缺乏跨委派边界保留风险语义的机制。这个缺口的深层原因在于多智能体架构的演进路径——系统设计者在构建协作能力时，关注的是任务如何被高效分解和完成，而并未充分考虑这些设计决策会如何被恶意攻击者利用。当一个原本需要集中式审视的复杂意图被拆分为多个局部合理的子任务时，风险信息也随之被碎片化，使得每个环节的安全检测都变得不完整。

这个发现对整个领域具有重要的警示意义。它表明多智能体系统的安全评估不能仅仅关注单个智能体的鲁棒性，还需要从系统层面考察信息在智能体间流动时的语义完整性。SafeFlow 提出的语义信息流视角为这一挑战提供了一个有价值的解决思路：通过显式追踪污点的传播路径，安全机制能够在保持任务分解带来效率优势的同时，弥补其引入的安全盲区。

框架的实用性也值得关注。SafeFlow 并不需要从头训练专门的检测模型，而是通过在现有多智能体系统中插入语义污点管理层和验证模块来实现防护。这种模块化的设计使得框架具有较好的迁移性，可以适配到不同架构的多智能体系统上。当然，这也意味着实现 SafeFlow 需要对底层系统进行一定程度的改造，对于黑盒部署的场景可能存在局限性。

在局限性方面，SafeFlow 的性能在很大程度上取决于语义污点表示的完整性和准确性。如果污点类型定义不够全面，或者污点传播规则存在遗漏，攻击者仍可能找到绕过检测的路径。此外，全局验证带来的额外计算开销在超大规模多智能体系统中可能变得显著，需要进一步优化以支持高并发场景。

对于后续研究而言，SafeFlow 的工作流验证机制可以被扩展为更通用的多智能体审计框架。自动化的风险上下文重建技术也有望应用于其他需要全局视野的安全场景。污点传播策略的优化——如何在不同任务类型间自适应调整传播粒度——是另一个值得探索的方向。这些潜在的研究机会都建立在 SafeFlow 所奠定的基础之上。

## 摘要
多智能体系统通过任务分解和角色专业化来提升能力，但这些机制本身也引入了一个重要的安全盲点：一个有害目标可以被拆解为局部上合理的子任务，从而让恶意意图规避任何单个智能体的检测。这是一个日益增长的社会影响挑战：处理敏感信息或具有重要后果工具的系统，会将常规委派转化为未经授权的披露或不安全的行动。我们认为，这种失败模式更适合被理解为一种语义信息流问题，而非单轮提示分类任务。为解决这一问题，我们提出了 SafeFlow，一个面向多智能体系统的防御框架，它将智能体间的恶意传播形式化为一个语义信息流问题。SafeFlow 将结构化的语义污染标记附加到根请求上，通过动态协作图进行传播，并在执行不可逆操作之前进行工作流级别的验证以重建全局风险上下文。在涵盖提示注入、基于越狱的不安全工具使用、风险代码执行和有害 Web 智能体行为的四个基准测试上进行评估，SafeFlow 在降低攻击成功率方面优于无防御基线和外部防御方法，同时保持较高的良性任务完成率和较高的配对安全—危害成功率。我们的研究表明，多智能体系统仍然缺乏跨委派边界保留风险语义的机制。这一缺口会使常规委派转化为影响个人和组织的隐私侵害或不安全行为。SafeFlow 在整个工作流中保持这种风险的可见性，使其在造成危害之前就被发现。

## Abstract
Multi-agent systems improve capability through task decomposition and role specialization, but these same mechanisms introduce an important safety blind spot: a harmful objective can be fragmented into locally plausible subtasks, allowing malicious intent to evade detection by any single agent. This is a growing social-impact challenge: systems handling sensitive information or consequential tools can turn routine delegation into unauthorized disclosure or unsafe action. We argue that this failure mode is better understood as a semantic information-flow problem than as a single-turn prompt classification task. To address this, we propose SafeFlow, a defense framework for multi-agent systems that formalizes malicious cross-agent propagation as a semantic information-flow problem. SafeFlow attaches structured semantic taints to root requests, propagates them through a dynamic collaboration graph, and performs workflow-level validation to reconstruct the global risk context before irreversible actions are committed. Evaluated on four benchmarks spanning prompt injection, jailbreak-based unsafe tool use, risky code execution, and harmful web-agent behavior, SafeFlow reduces attack success rates compared to undefended baselines and external defenses while retaining high benign task completion and a high paired safe--harm success rate. Our findings show that multi-agent systems still lack mechanisms for preserving risk semantics across delegation boundaries. This gap can turn routine delegation into privacy harms or unsafe actions that affect people and organizations. SafeFlow keeps this risk visible throughout the workflow, before it results in harm.
