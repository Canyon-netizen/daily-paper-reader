## 摘要
许多自动化多智能体系统设计方法在初始设计阶段优化提示词和拓扑结构，然后在后续样本上部署未更改的系统。这些样本中的经验很少被整合为可复用的系统更新，而以准确性为导向的设计可能产生较高的 token 成本。我们提出 EMAS（Evolving Multi-Agent System，演化多智能体系统），它利用这些经验来修订 MAS 的拓扑结构和提示词，无需更新 LLM 参数，既可提升准确性，也可降低成本。EMAS 将轨迹转换为结构化的诊断结果，明确指定修订操作与目标。它仅在相同诊断在多个样本中重复出现时才生成候选修订，并且仅在与当前 MAS 的配对验证满足相应接受标准时才应用该修订。在四个基准测试和两个 LLM 上，EMAS 在两个骨干模型上都取得了最高的任务加权整体准确率，并在 8 个模型–基准测试设置中的 6 个上达到最佳或并列最佳。在两个演化轮次内，EMAS 在 Kimi-K2-6 和 Qwen3.6-27B 上分别实现了 6.30% 和 20.10% 的任务加权准确率相对提升。在 Qwen3.6-27B 上的 MBPP 基准测试中，EMAS 将准确率从 55.09% 提升至 89.12%，同时将每任务的 token 使用量降低了 62.2%。这些结果表明，EMAS 能够将新样本中的经验转化为对 MAS 拓扑结构和提示词的可复用更新。

## Abstract
Many methods for automated multi-agent system design optimize prompts and topologies during an initial design stage and then deploy the resulting system unchanged on subsequent samples. Experience from these samples is rarely consolidated into reusable system updates, while accuracy-oriented designs may incur high token costs. We introduce EMAS (Evolving Multi-Agent System), which uses this experience to revise MAS topology and prompts without updating LLM parameters, either to improve accuracy or to reduce cost. EMAS converts traces into structured diagnoses that specify a revision operation and target. It generates a candidate revision only when the same diagnosis recurs across samples and applies it only if paired validation against the current MAS meets the corresponding acceptance criterion. Across four benchmarks and two LLMs, EMAS attains the highest task-weighted overall accuracy for both backbones and is best or tied in six of eight model--benchmark settings. Within two evolution epochs, EMAS achieves relative gains of 6.30% and 20.10% in task-weighted accuracy on Kimi-K2-6 and Qwen3.6-27B, respectively. On MBPP with Qwen3.6-27B, EMAS raises accuracy from 55.09% to 89.12% while reducing token use per task by 62.2%. These results show that EMAS can turn experience from new samples into reusable updates to MAS topology and prompts.

# EMAS 论文总结

## 1. 核心问题与研究动机

- **静态部署的局限**：现有自动化多智能体系统（MAS）设计方法（如 GPTSwarm、ADAS、AFlow、Symbolic Learning 等）在初始设计阶段一次性优化提示词与拓扑后即固定部署，未能将后续执行产生的新样本经验沉淀为可复用的系统更新。
- **准确性-成本权衡困境**：以准确性为导向的设计往往伴随高昂的 token 成本，缺乏在固定 LLM 参数的前提下同时优化准确率与执行成本的统一机制。
- **演化稳定性风险**：如果允许系统持续演进，错误的修订同样会持久化，危及系统可靠性。因此需回答三个问题：修订目标定位、修订时机判定、修订回归控制。

## 2. 方法论

### 2.1 整体思想
将 MAS 视为由 LLM 调用节点（Step）和有向信息流边（Edge）构成的**有向无环图（DAG）**，通过"**结构化诊断 → 复发门控 → 配对验证 → 持久版本过渡**"四步机制实现系统级演化，LLM 参数全程冻结。

### 2.2 形式化定义
- **类别专属 MAS 状态**：
$$M_c^{(v)} = \left(G_c^{(v)}, P_c^{(v)}\right)$$
其中 $G_c^{(v)} = (V_c^{(v)}, E_c^{(v)})$ 表示图结构，$P_c^{(v)}$ 表示各节点提示词集合，$v$ 为版本号。
- **结构化诊断假设**：
$$h = (o, d, a, \ell)$$
$o \in \{\text{ACCURACY}, \text{COST}\}$ 为目标，$d$ 为缺陷类别，$a$ 为关联操作，$\ell$ 为规范化的目标位置。

### 2.3 六类原子修订操作
| 组件 | 操作 |
|------|------|
| Step | ADD-NODE、REMOVE-NODE、SPLIT-NODE |
| Edge | ADD-EDGE、REMOVE-EDGE |
| Prompt | PROMPT-ONLY |

### 2.4 复发门控与配对验证
- **证据累积**：同一假设 $h$ 须在 $\kappa_a$ 个不同样本中得到支持方可触发候选生成（ADD-NODE：$\kappa=1$；PROMPT-ONLY：$\kappa=6$；REMOVE-NODE：$\kappa=10$）。
- **配对验证接受规则**：
$$\text{Accept}_{\text{acc}}(\tilde{M}_c) \Leftarrow C(\tilde{M}_c) > C(M_c^{(v)})$$
$$\text{Accept}_{\text{cost}}(\tilde{M}_c) \Leftarrow C(\tilde{M}_c) \geq C(M_c^{(v)}) \wedge T(\tilde{M}_c) < T(M_c^{(v)})$$
其中 $C(\cdot)$ 为验证集正确数，$T(\cdot)$ 为总 token 数。

## 7. 优点

- **结构化诊断 + 复发门控**有效抑制单次异常样本触发的噪声修订。
- **配对验证**作为"安全阀"，显著降低破坏性简化（destructive simplification）的风险。
- **双目标演化机制**（accuracy 与 cost）并配以严格不同的接受阈值，统一了准确率与成本权衡。
- **可审计的系统级演化**：每步操作类型与位置均被规范化（h 中的 $a$、$\ell$），便于回溯与解释。
- **图式状态表示**将 Agent 内部的细粒度计算暴露为原子 Step，使拓扑级修订可操作。
- **类比清晰**：与模型训练并行的图示将"参数学习 vs. 系统学习"的概念对比直观化。

## 8. 不足与局限

- **非单调性与回看偏差**：39/93 的 E2 修订在 Test 上出现退化；主表结果依赖"测试集回看最佳检查点"，并非部署时可选的实时规则，存在选择偏差风险。
- **修订粒度受限**：单一有界编辑可能漏掉需协同修改的修复；复发并不意味着因果等价，结构化 key 仍可能合并不同成因的轨迹。
- **验证集固定**：反复使用同一 Validation 集可能引入适应性选择，导致对过拟合敏感。
- **反馈假设过强**：依赖正确性反馈（correctness feedback），对仅有部分反馈或无反馈场景适配受限。
