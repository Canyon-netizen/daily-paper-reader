## 摘要
长时程工具使用智能体必须对用户目标、领域策略、工具调用、模拟器状态以及延迟可验证奖励进行推理。强化学习（RL）天然契合这一场景，但多轮同策略展开会产生长上下文，同时特定模型的注意力层可能需要自定义掩码以及学习得到的 sink 归一化。我们提出了 SINKFLEX-RL，一个用于双重控制工具使用环境中强化学习的模块化训练系统。该系统结合了兼容 Gymnasium 的环境包装器、VERL 风格的展开数据流、无需独立价值模型的分组相对策略优化，以及一种 sink 感知的 FlexAttention 路径，旨在在因果掩码和滑动窗口掩码下保持模型特定的 sink 缩放。在一次初步的 Tau2Bench 零售场景运行中，验证奖励（mean@1）在训练早期为 0.25，在观察到的训练窗口后期升至 0.44，而训练得分与轨迹奖励代理指标也呈上升趋势。在固定配置的内存基准测试中，优化后的注意力路径在 4096 tokens 时将峰值显存从 28.06 GB 降低至 22.52 GB，降幅达 19.7%，并在测量的 8192-token 配置下仅使用 25.53 GB 即可运行，而 eager 基线在该配置下则出现显存不足。这些结果说明了将环境接口、强化学习数据流与注意力内核设计相集成，对于实现内存可行的长时程智能体训练的价值。

## Abstract
Long-horizon tool-using agents must reason over user goals, domain policies, tool calls, simulator state, and delayed verifiable rewards. Reinforcement learning (RL) is a natural fit for this setting, but multi-turn on-policy rollouts create long contexts, while model-specific attention layers may require custom masks and learned sink normalization. We present SINKFLEX-RL, a modular training system for RL in dual-control tool-use environments. The system combines a Gymnasium-compatible environment wrapper, a VERL-style rollout dataflow, group-relative policy optimization without a separate value model, and a sink-aware FlexAttention path designed to preserve model-specific sink scaling under causal and sliding-window masks. In a preliminary Tau2Bench retail run, validation reward (mean@1) rises from 0.25 early in training to $0.44$ later in the observed training window, while training-score and trajectory-reward proxies also trend upward. In a fixed-configuration memory benchmark, the optimized attention path reduces peak VRAM from 28.06GB to 22.52GB at 4096 tokens, a $19.7\%$ reduction, and runs the measured 8192-token configuration using $25.53$~GB where the eager baseline runs out of memory. These results illustrate the value of integrating environment interfaces, RL dataflow, and attention-kernel design for memory-feasible long-horizon agent training.

## 1. 核心问题与研究动机

- **研究场景**：长时程工具调用智能体（agent）需要在交互式环境中完成多轮对话、工具调用和策略推理，并在最终态才获得稀疏的可验证奖励。典型代表为 τ2-Bench 等 dual-control（用户与智能体均可影响状态）的客服类基准。
- **两大系统瓶颈**：
  1. **长上下文瓶颈 —— 多轮 on-policy rollout 会产生数万 token 的轨迹**，单条轨迹即对应 $n \times n$ 的注意力分数矩阵（如 $n=20{,}000$ 时即 $4\times 10^8$ 个位置），叠加 MoE 路由、激活值与优化器状态后，eager attention 在反向传播前即可能耗尽高带宽显存。
  2. **模型特定注意力兼容性瓶颈 —— 现代 MoE/长上下文模型常带有「可学习的 attention sink」与自定义 mask**，而 FlashAttention 等固定接口的融合内核无法暴露必要的辅助梯度路径和分数修改接口，导致 sink 缩放在因果+滑动窗口组合下失效。
- **本文定位**：将 agentic RL 视为「环境接口 + RL 数据流 + 注意力内核」的**系统集成问题**，而不是新算法问题。

## 2. 方法论：SINKFLEX-RL 训练系统

### 2.1 系统四大组件

1. **Gymnasium 兼容的双重控制环境封装**：统一 `reset/step` 接口，将自然语言回复、工具调用、终止三类模型输出路由到相应处理器，并将用户模拟器、工具实现、检查器逻辑封装在 wrapper 之外，便于跨 benchmark 复用。
2. **VERL 风格的 rollout 数据流**：rollout worker 负责多轮交互采样（每轮格式化观测 → 从 $\pi_\theta$ 采样 → 解析为动作 → 写入轨迹 buffer），终止后把 token 级对数概率、动作掩码、轨迹奖励与 episode 元数据交给 trainer。
3. **无独立 value model 的 GRPO 策略更新**：以组内采样替代 critic，节省显存与算力。
4. **Sink-aware FlexAttention 路径**：用可编程 mask 接口保留模型原生注意力语义，并以零值 sink 代数等价变换避免显式 sink token 的 KV 物化。

### 2.2 关键公式

- **任务实例与轨迹形式化**：
  $$E = (g,\ \pi_{SOP},\ A_{tool},\ s_0,\ u)$$
  $$\tau = \{(o_t, a_t, r_t, d_t, i_t)\}_{t=1}^{T}$$

- **GRPO 组内归一化优势**：
  $$\hat{A}_i = \frac{R_i - \mu(R_{1:G})}{\sigma(R_{1:G}) + \epsilon_A}$$

- **重要性采样比与截断**：
  $$\rho_{i,t}(\theta) = \frac{\pi_\theta(y_{i,t}\mid x, y_{i,<t})}{\pi_{\theta_{old}}(y_{i,t}\mid x, y_{i,<t})}$$
  $$\bar{\rho}_{i,t}(\theta) = \mathrm{clip}\!\left(\rho_{i,t}(\theta),\ 1-\epsilon_c,\ 1+\epsilon_c\right)$$

- **PPO 风格裁剪目标与 GRPO 损失**：
  $$J_{i,t}(\theta) = \min\!\left(\rho_{i,t}(\theta)\hat{A}_i,\ \bar{\rho}_{i,t}(\theta)\hat{A}_i\right)$$
  $$L_{GRPO}(\theta) = -\frac{1}{\sum_i T_i \cdot G}\sum_{i}\sum_{t} J_{i,t}(\theta) + \beta\, D_{KL}(\pi_\theta \Vert \pi_{ref})$$

### 2.3 零值 sink 代数等价变换

设可学习 sink logit 为 $s_\eta$，sink 的 value 向量为 $v_{sink}=0$。对查询 $q$：

$$O_{sink} = \frac{\sum_i \exp(q\cdot k_i) v_i + \exp(s_\eta)\cdot 0}{\sum_i \exp(q\cdot k_i) + \exp(s_\eta)} = \left(\frac{\sum_i \exp(q\cdot k_i)}{\sum_i \exp(q\cdot k_i)+\exp(s_\eta)}\right) O_{std}$$

令 $\ell = \log\sum_i \exp(q\cdot k_i)$，则

$$\alpha_{sink} = \sigma(\ell - s_\eta),\qquad O_{sink} = \alpha_{sink}\, O_{std}$$

即只需在标准注意力的 log-sum-exp 统计量上做一次 sigmoid 缩放，无需显式物化 sink 的 KV。

### 2.4 FlexAttention 实现模式

- **组合 mask**：因果约束 + 滑动窗口 + 始终可见前缀：
  $$M_{b,h,q,k} = \mathbb{1}[k \le q] \wedge \mathbb{1}[q-k \le w \vee k < p]$$
- **前向路径**：
  $$(z,\ \ell) = \mathrm{FlexAttention}(Q,K,V;\ \mathrm{BlockMask}(M))$$
  $$\alpha_{sink} = f_\eta(\ell),\qquad z' = z \odot \alpha_{sink}$$
  其中零值 sink 下 $f_\eta(\ell)=\sigma(\ell - s_\eta)$。
- **梯度流（链式法则）**：
  $$\nabla_z L = \nabla_{z'} L \odot \alpha_{sink}$$
  $$\nabla_{\alpha_{sink}} L = \sum_{j=1}^{d} \left(\nabla_{z'} L \odot z\right)_j$$
  $$\nabla_\ell L = \nabla_{\alpha_{sink}} L \odot f'_\eta(\ell)$$
  $$\nabla_\eta L = \nabla_{\alpha_{sink}} L \odot \frac{\partial f_\eta(\ell)}{\partial \eta}$$
- **工程优化**：
  - 通过 `torch.compile` + AOTAutograd 融合 FlexAttention 与 sink 缩放，避免 $O(n^2)$ Jacobian 物化；
  - 在 batch/head 维度共享 mask 元数据，依靠 kernel 侧广播，避免重复存储 block-sparse mask。

- **核心论点**：环境接口 + RL 数据流 + 注意力内核的**协同集成**即可显著提升长时程 agentic RL 训练的**显存可行性**，而新算法并非必要条件。

## 7. 优点

- **系统视角新颖**：把长时程 agentic RL 当成「环境封装 + RL 数据流 + 自定义注意力」的集成问题，三个抽象层各司其职，模块化好。
- **零值 sink 代数等价推导清晰**：用 sigmoid 缩放替代显式 sink KV，理论上既保留可学习 sink 的语义，又消除额外物化开销；并完整给出链式法则下的梯度闭式形式。
- **FlexAttention + AOTAutograd + torch.compile 的组合**：在不放弃融合内核性能的前提下，保留对自定义 mask、score 修改和辅助梯度路径的可编程控制，弥补了固定 FlashAttention 接口的盲区。
- **GRPO 替代 critic**：与 MoE + 长上下文叠加下的显存压力相契合，节省一个价值网络的存储/算力开销。
- **首次在 dual-control τ2-Bench 上端到端打通 RL 训练 + sink-aware attention**，具有工程示范意义。

## 8. 不足与局限

- **算法层面证据薄弱**：
  - 仅一个 τ2-Bench retail 域、一次运行、两个时间窗的趋势值，**无多 seed、无 optimizer baseline、无统计显著性检验**；
  - 数值从 dashboard 截图视觉估读，存在量化噪声；
  - 未消融 GRPO、KL 系数、组大小 $G$、截断 $\epsilon_c$ 等关键超参。
- **注意力路径评估不完整**：
  - 仅报告**峰值显存**，未给出吞吐量、wall-clock、加速器利用率、forward/backward 数值等价性测试；
  - 未单独消融 sink 缩放、`torch.compile` 融合、mask 广播等子优化各自的边际贡献；
  - 8192 tokens 仅证明「不 OOM」，未与 FlashAttention 等第三方融合内核做同口径对比。
- **泛化性存疑**：结论仅针对「large open-weight MoE transformer + τ2-Bench retail」组合，**未跨域（航空、其他客服）、跨模型架构（dense、Mamba 类）验证**。
- **部署与安全风险**：作者在 Ethics Statement 中也明确指出，工具调用智能体存在策略合规、用户欺骗、不安全工具调用、隐私泄露、模拟器过拟合等风险，当前系统**未声称具备部署成熟度**。
- **未触及的关键问题**：更长上下文（≥16K）、rollout 并行/分布式开销、用户模拟器质量对策略学习的影响、reward shaping、curriculum 与多样性采样等均未在文中展开。
