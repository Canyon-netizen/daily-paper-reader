## 摘要
大语言模型能够生成可执行程序，这使得我们可以直接对过程化内容生成器（而非单个关卡）进行搜索。我们在推箱子、塞尔达、危险戴夫和淘金者四个领域中研究了这种方法。每一轮运行通过语言模型的变异与交叉来演化完整的 Python 生成器。我们提出了持续抽象发现（Continual Abstraction Discovery, CAD），它将可复用原语从高适应度程序中提取到运行专用的辅助模块中。一项 2×2 实验将 CAD 与对一个固定的手写领域 API 的访问进行了交叉组合。完成的数据集包含 160 次完整运行，每个单元格中至少有十次 50 代运行。CAD 在全部八个领域与 API 比较中都提升了最终最佳适应度的均值。在所有使用 CAD 的运行中，学到的库被大多数后续程序所采用，并反复重新发现了验证、可达性以及结构性工具。这些结果支持如下结论：发现可复用原语能够改进针对内容生成器的演化程序搜索。

## Abstract
Large language models can generate executable programs, which makes it possible to search directly over procedural content generators rather than individual levels. We study this approach in Sokoban, Zelda, Dangerous Dave, and Lode Runner. Each run evolves complete Python generators through language-model mutation and crossover. We introduce Continual Abstraction Discovery, or CAD, which extracts reusable primitives from high-fitness programs into a run-specific helper module. A 2x2 experiment crosses CAD with access to a fixed hand-written domain API. The completed data set contains 160 complete runs, with at least ten 50-generation runs in every cell. CAD raises mean final best fitness in all eight domain and API comparisons. Across all CAD runs, learned libraries are adopted by most later programs and repeatedly rediscover validation, reachability, and structural utilities. These results support that discovering reusable primitives improves evolutionary program search for content generators.

# 论文总结：基于程序搜索与持续抽象发现的过程化内容元生成

## 1. 核心问题与整体含义

- **研究背景**：传统过程化内容生成（PCG）多在**单个关卡层面**进行搜索，依赖针对特定游戏机制手工构造的生成器。这种方式工程量大、跨游戏不可复用，且生成器多表现为神经网络等不透明结构，难以检视与编辑。
- **核心问题**：能否直接在**生成器程序空间**进行搜索（即"过程化内容**元**生成"，Procedural Content Metageneration）？如何在搜索过程中让生成器自动获得更丰富的可复用原语？
- **动机**：随着大语言模型（LLM）展现出强大的代码生成能力，将 LLM 作为演化循环中的变异/交叉算子成为可能。但搜索原始代码时，可达性、修复、实体归一化等公用工具会在不同个体中被反复重写；若仅提供固定 API，原语词汇又会被搜索启动前的能力锁死。

## 2. 方法论

### 2.1 程序表示
- 每个个体是**完整的 Python 程序**，对外固定接口为 `generate(context_dict)`，接收网格尺寸与初始关卡并返回二维瓦片网格。
- 所有候选程序共享同一评测接口，可编译、可执行、可检视。
- 全部运行从一个**最小种子程序**（仅含瓦片常量与空白/复制的初始网格，无生成逻辑）开始。

### 2.2 演化搜索
- 维护一个**归档（archive）**，保存所有成功评测的个体。
- 每代按**适应度比例**采样父代；当归档个体数 ≥ 2 时以 0.25 概率执行**交叉**，否则执行**变异**；交叉失败时回退到变异。
- **变异**：LLM 在给定父程序、领域描述、累计运行记忆、固定生成器契约后，要求产生"行为上显著不同"的新程序。
- **交叉**：LLM 在两个父程序基础上组合兼容机制，输出一个可执行的完整程序。
- **鲁棒性流水线**：程序必须通过编译并完成 5 次烟雾测试中的至少 3 次；失败时调用 LLM 校正（最多 4 次）；整代无有效候选则记适应度为 0。
- **反思记忆**：每代结束后由 LLM 生成结构化记录（尝试的改动、结果、全局经验），其累积的全局经验会取代原始父代反馈，作为后续变异/交叉提示的一部分。

### 2.3 评测与适应度
- 每个候选程序执行 30 次，关卡由 PCG Benchmark 的质量（Q）、有效性（V）、多样性（D）函数评估。
- 适应度定义为三者的均值：

$$
F = \frac{1}{3}(V + Q + D)
$$

其中 $V$ 为质量等于 1 的关卡比例，$Q$ 为平均关卡质量，$D$ 为关卡间平均成对多样性，均落在 $[0,1]$。崩溃或验证失败者适应度为 0。

### 2.4 持续抽象发现（CAD）
- 从第 8 代起，每 5 代执行一次抽取：
  1. 识别本运行中处于适应度**第 75 百分位及以上**的程序；
  2. 由 LLM 分析这些程序并提出可复用的工具函数；
  3. 抽取出的函数必须通过编译与烟雾测试（最多 2 次编译修正）；
  4. 对原程序进行**重构（refactor）**，使其调用新工具函数；
  5. 重构仅在**固定种子的行为测试**与原程序输出一致时被接受；接受者重新评测并更新归档条目。
- 当重构成功率在 10 代热身期后仍低于 30% 时，自动禁用重构。
- 抽取出的函数被登记到**运行专用辅助模块**（helper module），后续变异/交叉/重构均可调用其中函数。

## 3. 实验设计

- **领域（4 个，均来自 PCG Benchmark）**：
  - **Sokoban**：5×5 日式推箱子谜题；
  - **Zelda**：7×11 地牢探险，需取钥匙并避开怪物到达出口；
  - **Dangerous Dave**：7×11 平台跳跃，避开尖刺取钥匙到出口；
  - **Lode Runner**：11×16 益智平台，玩家只能行走、挖地、爬梯、走绳索，需收集所有金块并避开敌人。
- **Benchmark**：PCG Benchmark 的质量与多样性输出，主要由 A* 求解器与行为/视觉特征计算得出；每次生成器调用的时限为 2 秒。
- **2×2 因子设计**：对每个领域，分别交叉两个因子——
  - **CAD**：开 / 关；
  - **Expert API**：开 / 关（手写助手库，含实体归一化、可达性、修复、领域结构等原语，如 `connect_floors_with_ladder`、`ensure_one_player`）。

- 所有运行共享：相同最小种子、演化搜索、反思记忆、修正流水线、评测预算与适应度函数。
