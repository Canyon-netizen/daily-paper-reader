## 摘要
面向编码智能体的强化学习日益依赖长时间运行的智能体 harness 来管理工具集成、代码库上下文与执行反馈。然而，这些 harness 的原生执行环境与策略梯度训练之间天然存在错位：环境崩溃与奖励攻击会污染结果信号，而训练-推理差异则导致 rollout 行为与策略更新脱钩。为此，我们提出 LEGO-RL，一个在不修改 harness 内部控制流的前提下，将原生编码智能体 harness 与可扩展策略梯度优化相衔接的框架。LEGO-RL 建立在三大支柱之上：（1）忠实的优化，通过进程内 LLM 代理捕获原始生成流以实现 token 级对齐，并支持训练端的对数概率鲁棒重计算，即使在 harness 侧发生压缩或重新序列化的情况下依然有效；（2）可靠的执行，借助具备镜像缓存与分阶段防御的可扩展沙箱编排来缓解奖励攻击；（3）可观测的训练，通过一个自动化校验与监控的集成插件，配合用于细粒度轨迹诊断的实时 UI。我们在三个原生编码智能体 harness 上使用 GSPO 训练稀疏 MoE 模型 Qwen3.5-35B-A3B 以评估 LEGO-RL。实验结果显示，LEGO-RL 在 SWE-bench Verified 上将 Qwen3.5-35B-A3B 在 OpenHands SDK（64.0% 提升至 70.4%）、Claude Code（62.4% 提升至 68.2%）以及 OpenCode（57.2% 提升至 66.6%）上的表现均显著提升，同时保持 rollout 与训练之间的概率相关性高于 0.99。

## Abstract
Reinforcement learning for coding agents increasingly relies on long-running agent harnesses to manage tool integration, repository contexts, and execution feedback. However, the native execution environments of these harnesses are inherently misaligned with policy-gradient training: environmental crashes and reward hacking corrupt outcome signals, while train-inference discrepancies decouple rollout behavior from policy updates. To address this, we present LEGO-RL, a framework that bridges native coding-agent harnesses with scalable policy-gradient optimization without modifying their internal control flow. LEGO-RL is built upon three pillars: (1) faithful optimization via in-process LLM proxying that captures raw generation streams for token-level alignment and robust trainer-side log-probability recomputation, even under harness-side compaction or re-serialization; (2) reliable execution via scalable sandbox orchestration featuring image caching and stage-wise defenses to mitigate reward hacking; and (3) observable training through an integrated plugin that automates validation and monitoring, paired with a Live UI for granular trajectory diagnostics. We evaluate LEGO-RL by training the sparse MoE model Qwen3.5-35B-A3B with GSPO across three native coding-agent harnesses. LEGO-RL improves Qwen3.5-35B-A3B across OpenHands SDK (64.0% to 70.4%), Claude Code (62.4% to 68.2%), and OpenCode (57.2% to 66.6%) on SWE-bench Verified, while maintaining a rollout-training probability correlation above 0.99.

# LEGO-RL 论文总结

## 1. 核心问题与研究动机

编码智能体（coding agent）的强化学习（RL）训练日益依赖长时运行的智能体 harness（如 SWE-agent、Claude Code、OpenHands SDK、OpenCode 等）来管理提示词构造、工具调用、代码库上下文与执行反馈。然而，将这些原生 harness 直接接入策略梯度训练面临三重系统性错位：

- **执行层错位**：沙盒崩溃、依赖错误、验证器配置错误、超时与奖励攻击（reward hacking）会丢弃昂贵轨迹或污染奖励信号，且在异步流水线中难以定位。
- **轨迹层错位**：harness 可能进行提示词重新序列化、上下文压缩或历史重写，导致从最终轨迹重建的训练样本无法精确解码回 rollout 时采样的 token 序列，从而破坏训练端的 log-probability 重计算。
- **模型层错位**：稀疏 MoE 模型在 rollout 与训练之间若专家路由不一致，即使 token 序列相同也无法忠实复现行为。

此外，通用 RL 框架通常要求将智能体适配到框架定义的 rollout 接口，而 harness 原生方法在可扩展执行、奖励完整性保护与轨迹级诊断方面仍不充分。LEGO-RL 的目标是在**不修改 harness 内部控制流**的前提下，将原生编码智能体 harness 桥接到可扩展的策略梯度优化。

## 2. 方法论

### 2.1 整体架构与三大支柱

LEGO-RL 构建于 verl 与 Harbor 之上，由三大支柱组成：

1. **忠实优化（Faithful Optimization）**：通过进程内 LLM 代理（In-Process Proxy）在模型服务边界捕获 rollout token 流，确保 token 级对齐与训练端 log-probability 鲁棒重计算；对稀疏 MoE 模型回放（replay）rollout 时的专家路由决策。
2. **可靠执行（Reliable Execution）**：可扩展的沙盒编排、Nydus 懒加载镜像缓存与分阶段防御机制保护奖励完整性，并按终止状态过滤与恢复轨迹以避免异步训练被失败轨迹破坏。
3. **可观测训练（Observable Training）**：集成插件自动化运行校验与监控，配套 Live UI 提供细粒度轨迹诊断。

### 2.2 形式化目标

任务实例 $x = (q_x, R_x, V_x)$ 从任务池 $\mathcal{D}$ 中采样，harness $H$ 在每轮 $t$ 将状态 $s_t$ 映射为上下文 $c_t = H(s_t)$，策略 $\pi_\theta$ 生成 $a_t \sim \pi_\theta(\cdot \mid c_t)$。Rollout 为模型 API 实际交换的 prompt-response 序列 $\tau = \{(c_1, a_1), \ldots, (c_T, a_T)\}$，验证器给出二元终端奖励 $r(x, \tau) = V_x(s_{T+1}) \in \{0, 1\}$。仅策略生成的 token 位置 $M(\tau)$ 参与训练。

使用组相对优势估计（group-relative advantage），主要实验采用 GSPO 序列级替代目标：

$$
J_{\text{GSPO}}(\theta) = \mathbb{E}\left[\frac{1}{G}\sum_{i=1}^{G} w(\tau_i) \min\left(\sigma_i(\theta) \hat{A}_i, \mathrm{clip}(\sigma_i(\theta), 1-\epsilon_{\text{low}}, 1+\epsilon_{\text{high}}) \hat{A}_i\right)\right],
$$

其中 $\sigma_i(\theta) = \left(\frac{\pi_\theta(\tau_i)}{\pi_{\theta_{k'}}(\tau_i)}\right)^{1/|M(\tau_i)|}$，$\theta_{k'}$ 为生成该组样本的策略版本，$w(\tau_i) \in \{0,1\}$ 过滤掉基础设施/执行失败导致的无效轨迹。非对称裁剪界 $\epsilon_{\text{low}} < \epsilon_{\text{high}}$ 允许序列级比率有更多向上移动空间。

### 2.3 忠实性要求

$$
\ell^{\text{train}}_{i,(t,j)}(\theta_{k'}) \approx \ell^{\text{roll}}_{i,(t,j)}, \quad \forall (t,j) \in M(\tau_i)
$$

在相同权重 $\theta_{k'}$ 下，训练端重计算的 log-probability 必须与生成时记录的值在数值精度内一致。该一致性要求 token ID、响应掩码、策略权重完全匹配，并且对稀疏 MoE 模型需复用行为策略的专家路由。异步训练中策略版本 $\theta_k$ 领先于 $\theta_{k'}$ 的 staleness 通过式 (1) 的重要性比率校正，而非捕获错误。

### 2.4 进程内代理（In-Process Proxy）

- 在提供方 API 边界捕获 token ID、log-probability、响应掩码与生成元数据；
- 在消息粒度上对齐连续上下文：系统/用户/工具结果消息必须精确匹配，工具调用通过稳定标识符与函数名关联，以避免参数重序列化改变捕获的策略 token；
- 子智能体调用从父捕获会话中隔离，防止其 token 进入训练轨迹；
- 无法可靠对齐的内容将被排除而非从修改后的转录中重建。

### 2.5 沙盒与奖励完整性

- 支持 Docker、Kubernetes、本地/远程容器、EC2/ECS 等多后端；
- Nydus 懒加载快照器按需流式加载镜像分片，避免全镜像复制；
- 智能体运行时与评分工具链以只读挂载方式共享，而非每次试验重装；
- 奖励完整性防御：特权 sidecar 控制网络访问、执行期间隐藏代码库历史、评分依赖打包进任务镜像、扣留测试文件直至评分阶段。

## 6. 主要结论与发现

- **SWE-bench Verified 显著提升**（同初始检查点）：
  - OpenHands SDK：$64.0\% \to 70.4\%$（+6.4 pp）
  - Claude Code：$62.4\% \to 68.2\%$（+5.8 pp）
  - OpenCode：$57.2\% \to 66.6\%$（+9.4 pp）
- 超越新一代基座 Qwen3.6-35B-A3B 在三个 harness 上分别高 3.0/4.8/6.0 pp，超过基座代际差距本身；
- **训练-推理忠实性**：rollout 与训练概率的 Pearson 相关中位数在三种 harness 上均 $\geq 0.998$，每轨迹 $|\Delta \log p|$ 的 p99 不超过 $3\times 10^{-3}$；
- **MoE 路由一致性**：回放 rollout 路由决策将使 rollout-training 相关性从 0.9946 提升至 0.9993，平均 $|\Delta \log p|$ 从 0.0062 降至 0.0025，专家重叠度 0.996，top-1 一致率 0.985；
- **行为变化**：OpenHands SDK 下"修改文件后回读"的比例从 73.6% 升至 98.1%，首次编辑前探索文件数从 3.5 增至 6.9，但错误恢复比例仅由 63.9% 升至 66.8%；
- **难度信息量漂移**：随策略提升，全错组占比下降但全对组占比上升，使零变异组比例在 OpenHands SDK 下由 44.7% 升至 51.4%，表明任务难度具有策略相对性；
- **系统效率**：异步训练相比同步训练在 7.5 小时窗口内步数从 3 提升至 7（2.5× 步骤时间缩减），修正优化器吞吐量差异后仍约 1.9× 加速；懒加载镜像相比 OCI 全量拉取，100 张镜像冷启动中位数加速 1.7×、最大 23×，网络流量由 21.6 GB 降至 1.59 GB，磁盘写入由 65.6 GB 降至 5.29 GB。

## 7. 优点

- **真正的 harness 原生**：不修改 harness 内部控制流，新增 harness 仅需轻量适配器，复用训练流水线；
- **忠实性工程完备**：在消息粒度做上下文对齐、子智能体隔离、token 级捕获与掩码管理，使异步训练下的策略梯度仍具可靠性，并对 MoE 模型专门处理路由回放；
- **奖励完整性系统化防御**：六类失效模式（读取 git 历史、下载参考修复、修改测试文件、评分器应用参考补丁、评分器需网络访问、构建不完整）均有对应防御并量化发生率；
- **可观测性强**：Live UI 提供终止原因分解、阶段级时序、轨迹浏览器、任务网格、训练-推理一致性面板、AI 辅助分析；将指标异常与底层执行/轨迹证据直接关联；
- **系统效率优化充分**：Nydus 懒加载、镜像缓存、预构建任务镜像、挂载运行时、异步调度、分阶段超时——多种手段协同降低长时编码任务的训练开销；
- **公开透明**：框架、训练模型、数据集全部开源，社区可复现；
- **诚实报告局限**：明确指出单模型、单次运行、部署环境依赖等问题。

## 8. 不足与局限

- **模型与配置覆盖窄**：所有实验仅使用 Qwen3.5-35B-A3B，每个 harness 单独训练，未验证其他架构与混合 harness 训练的泛化性；
- **运行方差未量化**：生产规模训练成本限制了每个主配置仅一次运行，训练收益与系统效率的运行间方差未知；
- **奖励粒度粗**：可执行验证提供的是二元终端奖励，无法对错误恢复等行为进行中间信用分配；
- **奖励完整性防御非完备**：所提防御针对已观察到的失效模式，不保证对所有可能的奖励利用策略鲁棒；
- **沙盒与镜像传输加速依赖部署环境**：所报告加速是当前实现下的测量，非 LEGO-RL 的普适性质；
- **诊断分析非因果验证**：辅助分析提供的是基于执行与轨迹证据的"可能原因"，而非自动化因果验证；
- **训练-推理一致性的边际退化**：在策略崩塌运行中 rollout-training 一致性从 0.995 降至 0.851（附录 C），表明在极端漂移下捕获机制本身可能受连带影响；
- **难度信息量随训练衰减**：固定任务池可能逐步丧失组相对监督的可用信息量，需动态任务选择机制。
