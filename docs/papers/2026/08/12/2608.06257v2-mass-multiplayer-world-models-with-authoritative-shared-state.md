## 摘要
当前视频世界模型在多玩家环境中表现不佳，因为它们将世界状态与视图相关的视觉隐变量纠缠在一起，导致计算冗余、视图不一致以及可扩展性差。我们提出 MASS（Multiplayer world models with Authoritative Shared State，具有权威共享状态的多玩家世界模型）以解决这一局限性。受多玩家游戏架构的启发，MASS 将世界动力学与视图渲染解耦。一个学习得到的状态逻辑引擎从联合动作推进一个全局的、权威的类型化状态，无需任何手写的转移函数，作为唯一的循环记忆和同步参考。从这个共享状态出发，一个学习得到的渲染引擎按需为任何请求的相机生成独立且一致的视图。这种显式解耦使 MASS 在一个匹配的多玩家贪吃蛇基准上，相较于最先进的多视图基线，实现了更高的状态精度和更低的跨视图不一致性。它能够推进包含 1,024 个并发玩家、持续 10,000 个循环步长的预测世界。我们的结果表明，显式的权威状态建模为可扩展且一致的多智能体世界模拟提供了实用基础。

## Abstract
Current video world models struggle in multiplayer environments because they entangle world state with view-dependent visual latents, leading to redundant compute, view inconsistencies, and poor scalability. We propose MASS (Multiplayer world models with Authoritative Shared State) to resolve this limitation. Inspired by multiplayer game architectures, MASS disentangles world dynamics and view rendering. A learned Logic Engine advances a global, authoritative typed state from joint actions without any hand-written transition function, acting as the sole recurrent memory and synchronization reference. From this shared state, a learned Rendering Engine generates independent and consistent views for any requested camera on demand. This explicit disentangling allows MASS to achieve superior state accuracy and lower cross-view inconsistency compared to state-of-the-art multi-view baselines on a matched multiplayer Snake benchmark. It advances predicted worlds with 1,024 concurrent players for 10,000 recurrent steps. Our results show that explicit, authoritative state modeling provides a practical foundation for scalable and consistent multi-agent world simulation.

## 1. 核心问题与研究动机

当前视频世界模型（如 GameNGen、Oasis、DIAMOND、Genie、WHAM 等）以像素或视觉潜变量作为循环载体，将世界状态与视角相关的视觉表征纠缠在一起。在多玩家场景下，这一设计暴露出三个根本性缺陷：

- **计算冗余**：上千名玩家共享同一世界，但每个视角都需要独立维护一份循环历史，对同一共享内容进行了上千次重复计算；
- **视角不一致**：不同视角的循环历史相互独立，可能对同一实体（如玩家位置）产生相互矛盾的状态估计；
- **扩展性差**：仿真成本与被观察视角数量线性耦合，无法支持大规模多人模拟。

已有的多玩家生成模型（Gamma-World、MultiWorld、MultiGen、WanToFight、Solaris 等）虽然引入了全局视觉表征、稀疏注意力或外部记忆，但其共享表征仍以视觉化、密集或外部维护的形式存在，缺乏一个**类型化的、可直接评估的权威状态**。受在线游戏权威服务器架构（服务器推进唯一权威状态、客户端按版本快照渲染）的启发，本文提出 MASS，将该契约引入学习型世界模型中。

## 2. 方法论

### 2.1 核心思想：显式解耦世界动态与视图渲染

MASS 将学习型仿真拆分为两个独立模块：

- **Logic Engine（逻辑引擎）**：唯一推进共享状态的学习组件；
- **Rendering Engine（渲染引擎）**：从共享状态按需生成任意相机视角的图像。

预测出的类型化状态同时承担三种角色：**循环记忆、同步对象、所有客户端视图的源头**。

### 2.2 关键技术细节

**(1) 游戏模式（Schema）与世界状态分词器**

$$\Sigma_g = \{(\text{kind}_j, \text{fields}_j, \text{count}_j)\}_{j=1}^{J_g}$$

$$s_t = \{\rho_t^1, \dots, \rho_t^{K_g}\}, \quad K_g = \sum_j \text{count}_j$$

$$u_t^i = \mathcal{T}_{\Sigma_g}\bigl(\rho_t^i, c_t^i, a_t^{\pi(i)}, e_t^i\bigr)$$

其中 $c_t^i$ 为当前状态的局部邻域窗口，$a_t^{\pi(i)}$ 为该实体所属玩家的动作，$e_t^i$ 为对应的随机性（如食物生成）。

**(2) Logic Engine**

采用 decoder-only Transformer（宽度 256、6 层、8 头、MLP 膨胀比 4）执行逐记录自回归预测。世界级转移为：

$$\hat{s}_{t+1} = \mathcal{F}_\theta(\hat{s}_t, a_t, e_t)$$

其概率分解为：

$$p_\theta(s_{t+1} \mid s_t, a_t, e_t) \approx \prod_{i=1}^{K_g}\prod_{j} p_\theta\bigl(y_{t+1}^{i,j} \mid u_t^i, y_{t+1}^{i,<j}\bigr)$$

注意力局限在单记录序列内，跨记录交互通过共享状态提供的邻域上下文 $c_t^i$ 注入。预测掩码约束每个输出位置仅取合法字段值；动态选择器强制排序、唯一性等跨记录约束。最终装配为权威状态：

$$\hat{s}_{t+1} = \mathcal{A}_{\Sigma_g}\bigl(\{\hat{\rho}_{t+1}^1, \dots, \hat{\rho}_{t+1}^{K_g}\}\bigr)$$

**(3) Rendering Engine**

对相机 $i$ 先执行模式驱动的相机局部投影 $P_i$，将占用、所属实体、玩家身份、深度等栅格化为 16 通道张量，再由几何感知的残差 U-Net 渲染为 RGB：

$$\hat{o}_t^i = \mathcal{R}_\phi\bigl(P_i(\hat{s}_t), \kappa^i\bigr)$$

观察模型分解为各相机独立条件生成：

$$p_\phi(\hat{o}_{C_t}^t \mid \hat{s}_t, \kappa_{C_t}) = \prod_{i \in C_t} p_\phi(\hat{o}_t^i \mid P_i(\hat{s}_t), \kappa^i)$$

**(4) 服务器与客户端逻辑**

权威服务器每 tick 发布版本化快照：

$$T_{\text{server}} = T_{\text{logic}}(N) + C \cdot t_{\text{sync}}(S)$$

渲染负载与相机数 $C$ 线性增长，但世界转移仅执行一次。当服务器更新延迟时，客户端利用同一 Logic Engine 用本地动作推进自身持有的最新权威状态，其他玩家动作置为 no-op；本地化身在 1–8 步间隔内位移严格为 0。

### 2.3 算法流程（Algorithm 1：单次共享世界更新）

1. $R_t \leftarrow \text{Records}_{\Sigma_g}(\hat{s}_t)$
2. 对每条记录 $\rho_t^i \in R_t$：构建邻域 $c_t^i$、分词 $u_t^i$、解码得到 $\hat{\rho}_{t+1}^i$
3. 装配 $\hat{s}_{t+1} \leftarrow \mathcal{A}_{\Sigma_g}(\{\hat{\rho}_{t+1}^i\}_{i=1}^{K_g})$，更新版本 $v_{t+1} \leftarrow v_t + 1$
4. 对每个相机 $c \in C_{t+1}$：投影并渲染 $\hat{I}_{t+1}^c \leftarrow \mathcal{R}_\phi(x_{t+1}^c)$
5. 返回 $(\hat{s}_{t+1}, v_{t+1}, \{\hat{I}_{t+1}^c\}_{c \in C_{t+1}})$

## 3. 实验设计

### 3.1 数据集与场景

- **Matched Snake**：48×48 网格上 $N \in \{2,4,8\}$ 玩家。训练 128 episodes/规模、测试 32 episodes/规模，128 tick 滚动，128×128 分辨率；
- **跨游戏原生数据集**：Breakout（3466/855 transitions）、Tile Merger（5729/1916）；
- **1,024 实体规模**：Snake、Crate Pusher、Pac-Man，每个 1024 受控实体槽位；
- **长周期压力测试**：Snake 至 $H=4096$、及含 1,024 玩家 10,000 步长序列；
- **8 游戏渲染对比**：Snake、Crate Pusher、Pac-Man、Tank Battle、Lunar Touchdown、Frogger、Tron、Bomberman。

### 3.2 对比方法

- **MultiWorld**（$\sim 5.60$B 参数，原耦合多视角扩散）：官方代码在匹配数据上重训；
- **B-PV**：每视角独立视频预测器（8.13M 参数）；
- **B-SL**：共享视觉潜变量（12.72M 参数）；
- **B-UN**：用密集联合状态 U-Net 替换类型化载体的消融（3.69M）；
- **额外逻辑基线**：RSSM、独立头 CNN；
- **自身**：MASS 5.66M 类型化 Transformer。

所有方法接受相同的训练集、动作流、相机路径与 20,000 更新预算（除 MultiWorld 35 epochs 外）。

### 3.3 评价指标

- 图像层：LPIPS、PSNR、Object PSNR、SSIM；
- 语义层：Parser（前景 F1）、Count、Position、Event F1、Cross-view Disagreement、Invalid；
- 逻辑层（直接评估）：Semantic、Active、Position、Full exact、Structural Validity、Contradiction；
- SRSC（State-Referenced Semantic Correctness）：Qwen3.5-27B 作为 VLM 法官，分 Logic / Renderer-GT / Renderer-Pred / End-to-end 四轴。

## 4. 资源与算力

- 计算平台：东京科学大学的 **TSUBAME4.0** 超级计算机（致谢中明确声明）；
- 精度：**bfloat16**，AdamW（lr $2\times10^{-4}$，weight decay $10^{-4}$，batch size 8，grad clip 1.0）；
- 匹配 Logic Engine：20,000 次 teacher-forced 更新；
- 渲染器：原生分辨率 6,000 更新，匹配分辨率 20,000 更新；Pac-Man 逻辑引擎 100,000 更新；
- 推理端：在单块 **NVIDIA H100** 上测量 1024 视角渲染 sweep，时间从 189.6 ms（1 视角）到 842.4 ms（1024 视角）；
- 推理延迟：2 玩家规模 45.6 ms/tick（≈20 Hz 可用），1024 实体规模单步全状态推进，未给出精确 wall-clock。

论文未显式报告 GPU 数量与训练总时长（小时），是信息披露上的不足。

## 6. 主要结论与发现

- **状态精度与跨视角一致性同时领先**：在匹配 Snake 上 MASS 取得 Parser = 0.764、LPIPS = 0.098、Event F1 = 0.552、X-view = 0.000，6/7 指标最佳，且 Cross-view 不一致严格为 0（由构造保证）；
- **类型化载体是核心**：替换为密集联合状态（B-UN）后，LPIPS 仍为 0.123（次佳）但 Parser 跌至 0.000、Invalid 1.000；
- **状态可分离评估**：SRSC 显示渲染器在固定 ground-truth 状态下跨 horizon 不发生语义漂移（Snake Renderer-GT 63.8–75.0 无单调下降），证实误差主要源自 Logic Engine；
- **大规模可扩展**：1024 实体一次世界转移、10000 步长无崩溃，渲染成本与相机数线性增长而世界转移成本与相机数解耦；
- **客户端预测有效**：本地化身在 1–8 步缺更新内位移 0；oracle 输入下视图一致度恒为 1.000；
- **跨游戏可迁移**：同一 Logic/Rendering 架构仅更换 tokenizer、embedding 与权重即可支持 Breakout、Tile Merger、Snake、Crate Pusher、Pac-Man、Snake–N=1024 等多种设定。

## 7. 优点

- **架构层面**：首次将"权威服务器 + 客户端预测"模式系统地引入学习型世界模型，明确分离逻辑与渲染，使两者可独立评估、再组合；
- **状态可检查性**：类型化记录使实体持久性、位置精度、结构有效性能在生成图像前直接度量；
- **传输与服务化**：版本化类型化快照可直接作为客户端同步消息，无需独立隐藏层 RGB latent 修正网络；
- **公平对照设计**：精心设置了 4 类共享/非共享、密集/类型化基线，覆盖核心设计变量；
- **错误定位能力**：SRSC 四轴分解为模型可解释性提供了标准化诊断协议，Logic 轴与程序化状态指标的相关系数 $r=0.962$；
- **规模示范**：1024 实体、单 H100 完成 1024 视角 sweep，验证了"仿真一次、渲染任意"的工程合理性。

## 8. 不足与局限

- **场景仍局限于网格化 2D 街机游戏**：所有游戏均为栅格化、规则明确、状态可枚举的小型街机（Snake/Crate Pusher/Pac-Man/Breakout/Tile Merger/Tron/Frogger/Bomberman 等），缺少 3D、连续控制、开放域视觉或自然语言交互；
- **公平性瑕疵**：MultiWorld 5.60B 参数与 35 epochs 直接与 MASS 5.66M / 20k 更新对比，规模差距近三个数量级，削弱"最强基线"结论的说服力；
- **资源披露不足**：未给出 GPU 数量、训练总时长（小时）、$H{=}10000$ 长程实验的 wall-clock 成本；
- **客户端预测延迟实验局限**：oracle 路径在 anchor tick 中报告，但实验仅在 $N=1024$ Snake 内的 3 个 anchor tick 上评估，统计显著性有限；
- **SRSC 协议依赖 VLM 主观判断**：使用 Qwen3.5-27B 作为唯一法官，分数在 0–100 区间方差大，且 Renderer-GT 在 Crate Pusher 上偶现 75.0 与 100.0 之间的跳动，可能放大评分噪声；
- **像素保真度受限**：8 游戏中 PSNR 最低仅 23.72 dB（Tron），原生 RGB 视觉与商用游戏引擎仍有差距；
- **应用限制**：schema 需手动声明，跨游戏迁移仍需要新数据；Logic Engine 推理延迟 45.6 ms（双玩家）尚可，1024 实体规模下的实时性未明确承诺；
- **偏差风险**：训练集均来自引擎录制，外生随机性经"兼容性通道"或"未来食物生成"重放，未涵盖真实玩家风格分布；Matched Snake 中不含 N>8 的可解释性扩展实验。
