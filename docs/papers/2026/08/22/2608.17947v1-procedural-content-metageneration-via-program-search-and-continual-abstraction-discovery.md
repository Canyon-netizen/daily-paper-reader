## 摘要
大语言模型能够生成可执行程序，这使得可以直接在过程化内容生成器而非单个关卡上进行搜索。我们在推箱子、塞尔达、危险戴夫和淘金者四个领域中对这一方法进行了研究。每次运行通过语言模型的变异与交叉来进化完整的 Python 生成器。我们提出了持续抽象发现（Continual Abstraction Discovery, CAD），它从高适应度程序中提取可复用的基本单元，并将其整合到运行专属的辅助模块中。一项 2×2 实验将 CAD 与对固定手写领域 API 的访问进行了交叉组合。完成的数据集包含 160 次完整运行，每个单元格中至少有十次 50 代运行。在全部八个领域与 API 对比中，CAD 都提高了最终最佳适应度的均值。在所有使用 CAD 的运行中，学习到的库被大多数后续程序所采用，并反复重新发现了验证、可达性以及结构相关的实用工具。这些结果支持以下观点：发现可复用的基本单元能够改进面向内容生成器的进化式程序搜索。

## Abstract
Large language models can generate executable programs, which makes it possible to search directly over procedural content generators rather than individual levels. We study this approach in Sokoban, Zelda, Dangerous Dave, and Lode Runner. Each run evolves complete Python generators through language-model mutation and crossover. We introduce Continual Abstraction Discovery, or CAD, which extracts reusable primitives from high-fitness programs into a run-specific helper module. A 2x2 experiment crosses CAD with access to a fixed hand-written domain API. The completed data set contains 160 complete runs, with at least ten 50-generation runs in every cell. CAD raises mean final best fitness in all eight domain and API comparisons. Across all CAD runs, learned libraries are adopted by most later programs and repeatedly rediscover validation, reachability, and structural utilities. These results support that discovering reusable primitives improves evolutionary program search for content generators.

## 1. 核心问题与研究动机

- **传统 PCG 的局限**：游戏中的过程化内容生成（PCG）通常依赖为特定游戏手工定制的生成器，工程量大且难以复用；在关卡级搜索会面临难以跨关卡共享结构的问题。
- **元生成（metageneration）思想**：直接搜索"生成器本身"而非单个关卡，可摆脱神经黑盒的可解释性差问题，但仍需可执行、可检视、可编辑的表示。
- **LLM 的新机会**：大语言模型已具备编写并修改代码的能力，使其可作为进化循环中的变异与交叉算子，对完整 Python 程序进行程序级搜索。
- **关键空白**：原始代码搜索的"词表"在运行前固定，规模变大后验证、可达性、修复、结构构造等子程序会在不同候选中被反复重写；即使提供手工 API，词表仍然静态。
- **本文目标**：提出**持续抽象发现（Continual Abstraction Discovery, CAD）**机制，让可调用原语的集合在搜索过程中动态增长，从而提升面向生成器的进化程序搜索。

## 2. 方法论

### 2.1 程序表示
- 每个个体是一个完整的 Python 程序，必须定义 `generate(context_dict)`，输入为初始网格、宽、高，输出同形状的二维整数网格。
- 所有候选使用同一评测 harness 进行编译、执行、检视与评分；所有运行从一个只含瓦片常量与空白/复制初始网格的最小种子出发。

### 2.2 进化搜索
- 每代从 archive 中按 fitness-proportional 概率采样父代，适应度下限为 $10^{-6}$。
- 当 archive 中个体数 $\geq 2$ 时以 $0.25$ 概率执行交叉，否则退化为变异；交叉失败也回退为变异。
- 变异与交叉均由 LLM 完成；提示中包含父程序、领域描述、累积运行记忆与固定生成器契约；交叉要求融合两个父代的兼容机制。
- 鲁棒性管线：必须编译通过，且在 5 次冒烟测试中至少完成 3 次；失败触发 LLM 纠错调用，最多重试 4 次。
- 每代后由 LLM 进行"反思"，追加结构化条目到 per-run memory；累积的全局经验会替代原始 per-parent 反馈注入后续提示。

### 2.3 适应度评估
- 每个候选执行 30 次，使用 PCG Benchmark 的 quality、validity、diversity 三个指标。
- 适应度定义为：
$$
F = \frac{1}{3}(V + Q + D)
$$
其中 $V$ 为 quality 等于 1.0 的关卡占比，$Q$ 为平均质量，$D$ 为采样关卡对的平均两两多样性，三者均取值于 $[0,1]$；崩溃或验证失败者适应度归零。

### 2.4 持续抽象发现（CAD）
- 从第 8 代起，每隔 5 代触发一次：从本运行中处于 fitness 第 75 百分位及以上的程序里抽取可复用工具函数。
- LLM 抽取调用分析这些程序并提出辅助函数，必须能编译并通过冒烟测试，最多两次编译纠错。
- 对源程序进行重构以调用新辅助函数；只有当重构后程序在固定种子的行为测试上与原程序一致时才接受。
- 被接受的重构会重新评估并更新 archive 条目；当连续 10 代的重构成功率低于 30% 时自动关闭重构。
- 抽取得到的函数写入本次运行专属 helper 模块，后续变异、交叉与重构调用均可使用。
