## 摘要
大语言模型能够生成可执行程序，这使得可以直接针对过程化内容生成器而非单个关卡进行搜索。我们在推箱子、塞尔达、危险戴夫和淘金者四个领域中研究了这种方法。每次运行通过语言模型的变异与交叉来演化完整的 Python 生成器。我们提出了持续抽象发现（Continual Abstraction Discovery，简称 CAD），它能从高适应度程序中提取可复用的原语，并存入特定于本次运行的辅助模块中。一个 2×2 实验将 CAD 与是否可访问固定的手写领域 API 进行交叉组合。完整的数据集包含 160 次完整运行，每个单元格中至少有十次 50 代的运行。CAD 在全部八个领域与 API 的对比中都提升了最终最优适应度的平均值。在所有使用 CAD 的运行中，学习到的程序库被大多数后续程序所采用，并反复重新发现验证、可达性以及结构相关的实用工具。这些结果支持以下观点：发现可复用的原语能够改善针对内容生成器的演化式程序搜索。

## Abstract
Large language models can generate executable programs, which makes it possible to search directly over procedural content generators rather than individual levels. We study this approach in Sokoban, Zelda, Dangerous Dave, and Lode Runner. Each run evolves complete Python generators through language-model mutation and crossover. We introduce Continual Abstraction Discovery, or CAD, which extracts reusable primitives from high-fitness programs into a run-specific helper module. A 2x2 experiment crosses CAD with access to a fixed hand-written domain API. The completed data set contains 160 complete runs, with at least ten 50-generation runs in every cell. CAD raises mean final best fitness in all eight domain and API comparisons. Across all CAD runs, learned libraries are adopted by most later programs and repeatedly rediscover validation, reachability, and structural utilities. These results support that discovering reusable primitives improves evolutionary program search for content generators.

# 论文总结：通过程序搜索与持续抽象发现进行过程化内容元生成

## 1. 核心问题与研究动机

传统过程化内容生成（PCG）通常依赖针对特定游戏手工编写的"构造式生成器"，其工程成本高、跨游戏难以复用，且学界长期关注的是在**关卡空间**进行搜索，而非在**生成器空间**进行搜索。

- **痛点**：手工构造生成器难写；现有基于神经网络或强化学习的生成器多为"黑盒"，不可检查、不可编辑；搜索单个关卡不能跨关卡复用设计知识。
- **目标**：将搜索粒度提升到生成器程序本身，让大语言模型（LLM）直接对可执行 Python 程序进行变异与交叉进化，实现"程序化的程序化内容生成器生成"（procedural content metageneration）。
- **额外问题**：在生成器空间搜索时，可用词汇表过早固化。许多有用的子程序（如可达性检查、实体归一化、结构修复）会在不同候选中被反复重写。

## 2. 方法论

### 2.1 个体表示

每个个体是一个完整的 Python 程序，统一接口为 `generate(context_dict)`，输入为初始网格与尺寸，输出为整型二维网格。可包含局部辅助函数、常量与布局例程，但公共接口固定，便于统一编译、执行与评估。

### 2.2 进化搜索流程

- 从一个最小种子程序（仅含常量与空/拷贝的初始网格）出发，每次评估后将成功个体纳入存档（archive）。
- 每代按适应度比例从存档采样一个父代；当存档中个体 ≥ 2 时以 0.25 概率选择交叉，否则变异。
- 变异与交叉由 LLM 完成（Prompt 见论文附录 Prompt 1–2），生成完整可执行程序。
- **鲁棒性管线**：必须通过编译，并完成 5 次烟雾测试中至少 3 次；失败时调用 LLM 修正，最多重试 4 次（Prompt 3）。
- **反射式记忆**：每代结束后调用 LLM 整理一次"代际日志 + 全局经验"，后续变异/交叉基于该全局经验而非原始评估反馈（Prompt 4）。

### 2.3 适应度函数

每个候选执行 30 次采样，按 PCG Benchmark 输出计算：
- $V$：完全有效关卡比例
- $Q$：平均关卡质量
- $D$：所有关卡对的平均两两多样性

最终适应度为三者的平均：
$$F = \frac{1}{3}(V + Q + D),\quad V,Q,D \in [0,1]$$

崩溃或验证失败的候选直接得 0 分。

### 2.4 持续抽象发现（CAD）

从第 8 代开始，每隔 5 代执行一次：

1. 选取当代适应度处于前 25% 的高适应度程序；
2. 调用 LLM（Prompt 5）从这些程序中抽取可复用领域工具函数（如可达性 BFS、实体归一化、`ensure_one_player`），写入运行专属辅助模块 `helper_<domain>_<uuid>.py`；
3. 抽取出的函数须通过编译与烟雾测试，最多 2 次修正（Prompt 6）；
4. 对源程序进行**重构**（Prompt 7），把内联代码替换为对新辅助库的调用；仅当重构后程序在固定种子行为测试中与原程序行为等价时才接受；
5. 接受后重新评估并更新存档；
6. 若连续 10 代重构成功率 < 30%，则自动关闭重构功能；
7. 缺失函数时调用缺失脚手架提示（Prompt 8）补齐。

## 3. 实验设计

- **领域 / 数据集**：来自 PCG Benchmark 的 4 个基于瓦片的游戏

  - Zelda（塞尔达式地牢，7×11）
  - Dangerous Dave（危险戴夫平台跳跃，7×11）
  - Lode Runner（淘金者，11×16）
- **基准（Benchmark）**：PCG Benchmark [9]，使用其 quality、validity、diversity 三项官方指标（基于 A* 求解器与行为特征）；每个生成器调用限时 2 秒。
- **2×2 因子设计**：
  - CAD：有 / 无（搜索中动态抽取辅助函数）
  - Expert API：有 / 无（提供手工编写的固定领域 API，如 `connect_floors_with_ladder`、`ensure_one_player`）
- **对比设置**：四种条件 = Base、Base+CL、API、API+CL，每组合每个领域至少 10 次独立 50 代运行。
- **基线方法**：本质上是同一系统的不同开关组合，构成直接消融。

## 6. 主要结论与发现

1. **跨域一致有效**：CAD 在全部 8 个（4 域 × 2 API 水平）比较中均提高了最终最佳适应度，符号检验 $p = 0.008$。
2. **与专家 API 互补**：即使提供了手工编写的固定 API，CAD 仍能在 Lode Runner 等任务上显著进一步提升效果，说明"运行中学习"的词汇表与"先验 API"提供的信息并不冗余。
3. **唯一反直觉点**：Zelda 是唯一一个"有 API 优于无 API"的领域，作者解释为其机制相对简单，路径搜索与对象计数类 API 收益最大。
4. **学习库增长与采纳**：辅助库在前几次抽取周期内快速增长随后稳定；一旦开始被使用，采纳率在多数后续代际保持在 80% 以上，每个程序平均调用辅助函数 15–20 次。
5. **代码长度收敛**：在 Base 条件下，CAD 把最佳程序从约 370 行缩短到约 296 行；固定 API 条件下程序本来就较短（约 160 行），CAD 的压缩空间较小（约 173 行）。
6. **可复用原语反复被重新发现**：高频出现的辅助函数包括 `in_bounds`、`Entity Count Normalization`（28/29 次 CAD 运行）、`Ensure One Player`、`Grounded Empty Cells`（24 次）、`Find Player Position`、`Ladder Placement`、`Reachability BFS`、`Relocate Unreachable Entities`、`connected_components`（20 次）。
7. **领域特化效应**：CAD 在 Lode Runner 中抽象出"在金子旁放敌人以增加难度"的 `guard_gold`，在 Zelda 中抽象出"把敌人放在关键路径之外"的 `place_enemies_away_from_critical`，均显著影响后续生成器行为。

## 7. 优点与亮点

- **搜索粒度提升**：把 PCG 搜索从"关卡空间"推到"生成器程序空间"，使设计知识能跨关卡复用。
