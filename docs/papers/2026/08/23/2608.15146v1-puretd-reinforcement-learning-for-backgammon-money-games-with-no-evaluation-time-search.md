## 摘要
我们在无评估时搜索的设定下，重新审视 Tesauro 的 TD-Gammon 方法用于西洋双陆棋赌金局面。行棋与立方体行动（加倍立方体的使用）均通过自博弈强化学习（RL）从零开始学习，仅采用极少的人工编码逻辑，不使用任何专家特征。在此设定下，我们证明单纯的自我对弈强化学习足以训练出达到接近当前最先进水平的模型。具体而言，在含加倍选择的赌金局面中，我们的无搜索模型评估速度更快，且实力显著强于运行一步（1-ply）前瞻搜索的开源引擎 GNU Backgammon 与 Open Sage。

## Abstract
We revisit Tesauro's TD-Gammon for backgammon money games in the setting of no evaluation-time search. Both checker play and cube action (use of the doubling cube) are learned from scratch via self-play reinforcement learning (RL), with minimal hand-coded logic and no expert features. In this setting, we demonstrate that pure self-play RL suffices to train models that reach near-state-of-the-art playing strength. Specifically, for cubeful money games, our search-free model evaluates faster and is substantially stronger than the open-source engines GNU Backgammon and Open Sage running a one-move (1-ply) look-ahead search.

## 2. 方法论

### 2.1 形式化建模：MDP + Bellman 最优方程

- 把博弈建模为 MDP，固定参考玩家为最大化方 $V$，对手对应最小化 $-V$。
- Bellman 最优方程（简化版）：

$$
V^*(s) = \max_a \mathbb{E}_{s' \sim T(s,a)} \big[ V^*(s') \big]
$$

- 自博弈中双方按 $\arg\max$、$\arg\min$ 贪心选动作，并保留少量探索。
- 关键分解：把掷骰前位置记为伪状态 $x$，掷骰 $d\sim D$ 后得到 $s_{x,d}$，对应取值：

$$
V^*(x) = \mathbb{E}_{d\sim D} \Big[ \max_a V^*(\tilde T(s_{x,d},a)) \Big]
$$

由此引出两类训练目标。

### 2.2 训练目标：sampled backup 与 exact Bellman backup

- **0-ply（采样）目标**：

$$
y_{\text{sampled}}(x) = \max_a V(\tilde T(s_{x,d},a)),\quad d \sim D
$$

- **1-ply（精确 Bellman）目标**：

$$
y_{\text{exact}}(x) = \mathbb{E}_{d\sim D}\Big[\max_a V(\tilde T(s_{x,d},a))\Big]
$$

- 训练策略：先用 5× 更快的采样 backup 直到平台期，再切换到 exact backup 精细化。

### 2.3 网络结构与训练流程

- **MLP**（PyTorch 实现）：
  - 赌金模型：200 输入 → $[512,512,256,256]$，共约 562k 参数，全 ReLU 激活（取代 TD-Gammon 的 sigmoid）。
  - 概率 5 头（prob5）模型（无加倍）：196 输入 → $[512,512,256,128]$，约 528k 参数，5 个独立 sigmoid 输出 win/win-gammon/win-backgammon/lose-gammon/lose-backgammon 概率。
- **批式流水线**：每轮 1000 局自博弈生成数据，做一轮 mini-batch SGD（Adam）。
- **渐进扩张 + 跨任务迁移**（Net2Net 函数保留变换）：

$$
[80] \to [150] \to [150,150] \to [256,256] \to [512,512] \to [512,512,256] \to [512,512,256,256]
$$

并跨任务 warm-start：双赛点（DMP）→ 无加倍等值 → 有加倍赌金。每次迁移后做 20 轮学习率 warmup（从目标值 10% 线性上升）。所有权重保持可训练。

### 2.4 加倍立方体：动作空间扩展（与 Lin 2020 的关键纠错）

- 把 cube-offer 决策（`no_double` vs `offer_double`）加入动作空间：无骰子随机性，转移确定性，因此 sampled 与 exact 目标重合：

$$
y_{\text{sampled}}(s) = y_{\text{exact}}(s) = \max_a V(\tilde T(s,a))
$$

- 引入新增输入 `is_cube_action`（0/1 标志）区分「立方体决策状态」与「后续棋子走法状态」，以及三个 one-hot 立方体归属特征 `cube_centered`、`cube_own`、`cube_opp_own`，共 4 个立方体特征。
- **关键纠错**：Lin (2020) 缺少 `is_cube_action`，导致无法区分同一棋盘下的 cube-decision 与 no-double 状态，无法训练 no-double 转移，从而错过明显能 double/pass 的局势。本文对每次 cube-offer 都生成 TD 样本。
- **Take/drop**：当前用评估器贪心处理对手反应（前向推理），未显式建模为 RL 动作。
- **Jacoby 规则**：cube 居中、对手将 pass 时自动 double_pass（终止并赢 1 单位）。

### 2.5 输出归一化

有加倍模型输出「每立方体单位等值」$\tilde V(s)$，实际等值为 $\tilde V(s) \times \text{current\_cube\_value}$，利用赌金面值下的线性关系稳定数值范围。

### 2.6 算法伪代码（Algorithm 1）的核心逻辑

- 状态 $s$ 拼上「cube_centered / cube_own / 0 / 1」四位标志位。
- 计算：
  - $V_{\text{no\_double}} = \text{model}(s_{\text{no-recube}})$
  - $V_{\text{take}} = 2 \cdot \text{model}(s_{\text{dt}})$
  - $V_{\text{pass}} = 1$
  - $V_{\text{double}} = \min(V_{\text{take}}, V_{\text{pass}})$
- 选择使己方等值最大且符合 Jacoby 规则的立方体动作，对当前状态做一次 TD 更新。

  - 95% 置信区间均给出，统计谨慎。
- **总体评估**：设计较充分，但未涵盖 match play、不同棋盘 phase 的细分分析。

---

## 6. 主要结论与发现

- **纯自博弈 RL 即可**：无需专家特征、Janowski 公式或搜索，纯 TD(0) 风格训练出的 0-ply 网络在 2 亿盘自博弈后达到近乎 SoTA 水平（XG++ PR ≈0.94，已接近人类超 Grand Master 门槛 2.0）。
- **立方体可端到端学**：通过扩展动作空间 + `is_cube_action` 特征 + no-double 也生成训练样本，纠正 Lin (2020) 的概念缺陷，cube PR 从 2.13 降至 0.60。
- **速度优势显著**：0-ply PureTD 比 gnubg/Open Sage 的 1-ply 搜索至少快 2.5×，同时实力更强。
- **网络容量与扩展**：Net2Net 函数保留迁移 + 跨任务 warm-start + 任务间 LR warmup，显著加速训练，复现版本在 232M 盘后达到与生产模型统计不可区分的水平（$+1.5[-0.3,3.2]$ mEq/game）。
- **Exact Bellman backup 的价值**：替代/补充 α=0 采样目标，去除骰子方差；从 0-ply 到 1-ply 的精确备份带来单次最大跃升（≈+12 mEq/game，Figure 2）。

## 7. 优点与亮点

- **真正端到端**：唯一一项同时学棋子走法与 cube-offer 行动并对赌金面直接评估的工作，消除了对 Janowski 公式的依赖。
- **方法上的简洁性**：仅用 TD(0) + ReLU + 批训练 + exact backup + 渐进迁移，便复现/超越经典 TD-Gammon。
- **强基线 + 多维度评测**：头对头 + XG++ PR + gnubg 4-ply mEMG + 跨机器吞吐量，证据链较完备。
- **完整开源**：MIT 协议下放代码、训练好的模型与复现命令；网权 md5、commit hash 锁定版本。
- **公平性与鲁棒性检查**：剪枝开/关、自博弈 vs 混合博弈的离线评测均做交叉验证。
- **可拓展到 match play / 自博弈搜索**：未来可直接扩展到 MCTS 或 match-play，而不需重写动作空间。

## 8. 不足与局限

- **暂未覆盖 match play**：仅限 money games（cubeless/cubeful money），未涉及 match-length 的立方体策略与更长视野，限制了应用场景。
- **专注 0-ply**：未把最终模型与搜索深度结合进行系统性研究，仅附录给到 2-ply 离线结果；理论上更强的网络+搜索可能进一步提升，但本文未在端到端引擎层面做头对头验证。
- **未涉及 AlphaZero 类学习模型 MCTS**：未尝试 Stochastic MuZero 风格的 learned-model 规划，可能错过更大的强度上限。
- **Take/drop 未显式建模为 RL 动作**：当前用贪心对手反应近似，作者也承认这隐式被 cube-offer 学到，但缺乏更细实验验证。
- **网络规模 vs 评估速度权衡**：PureTD 0-ply 速度仍慢于两个开源引擎（5–12×），作者也指出 PyTorch 通用路径与手工 C++ 路径的差距；强 0-ply 网络与 1-ply 工程引擎间的差距是明示意图的「缺口」。
- **样本量偏边际的稳定度**：cubeful PR 的 95% 区间约 ±0.05，深度对比时仍有小幅重叠；头对头虽大样本，但只比了两个引擎，未与更商业级引擎（如 BGBlitz、Octopus、XG、Hedgehog）做大规模对照（这些多为闭源或无完整训练代码）。
- **特定代码细节的非客观性**：RL 模型对微小输入差异敏感，特别是加了 `is_cube_action` 后表 7 的消融展示了非平凡的定性改变，但只在 cubeful 单任务上验证。
- **算力披露粒度**：仅说「单台 64 核 Zen 5 + ≥24 GB GPU」，未详细报告 GPU 型号、显存占用、能耗等指标，难以精确复现训练成本。
