## TL;DR

Search-on-Graph-R1 将知识图谱导航能力从昂贵的前沿大模型中蒸馏到一个紧凑的 80 亿参数模型中。它利用每个问题的标准 SPARQL 查询为教师模型搭建脚手架，让教师在真实的 Freebase 服务器上执行遍历，从而生成扎根于知识图谱的训练轨迹。在 WebQSP、CWQ 和 GrailQA 三个基准数据集上，这个 8B 模型超越了我们对比中所有冻结权重的前沿大语言模型系统，并在 CWQ 上取得了对比系统中的最优成绩，同时训练过程不使用任何 LLM 评判器。

## 研究背景与动机

知识图谱问答（KGQA）是一项经典而重要的任务：给定一个自然语言问题，系统需要从一个庞大的结构化知识库（如 Freebase）中定位到正确答案。这要求从问题中识别出的主题实体出发，沿着若干关系边一步步导航，最终抵达答案所在的位置。

近年来，一种流行的做法是借助大语言模型的推理能力来实现知识图谱导航。具体流程通常是：让前沿 LLM 扮演"探索者"的角色，通过调用检索工具在图谱上逐步扩展搜索范围，直到找到答案。这种方法的思路很直觉——LLM 具备强大的推理和规划能力，理论上应该能胜任这种图上导航任务。

然而，这种方案面临一个根本性的瓶颈：它依赖前沿规模的 LLM 进行推理。大模型的推理成本极高，每进行一次问答都需要消耗大量的计算资源。这使得这类方法在实际部署中代价高昂，尤其是需要处理大量查询的场景。更关键的是，LLM 在图谱上的探索路径是它"自己决定"的，这条路径是否真的存在于知识图谱中、是否真的能导向正确答案，并没有任何保证——LLM 可能生成看似合理但事实上并不存在于图谱中的关系或路径。

Search-on-Graph-R1 的核心切入点正在于此：与其让模型在图谱上"自己探索出一条路"，不如利用每个问题的标准答案路径来引导训练过程。作者们的思路是，如果我们已经有了正确的 SPARQL 查询（它精确描述了从主题实体到答案的路径），为什么不直接用这个查询来"告诉"教师模型应该怎么走？这样生成的轨迹天然就是正确且扎根于真实知识图谱的。通过这种方式，可以把知识图谱导航能力高效地蒸馏到一个紧凑模型中，从而大幅降低部署成本。

## 方法

Search-on-Graph-R1 的方法分为两个阶段：监督微调（SFT）和强化学习（RL）。整个pipeline的设计围绕一个核心洞察展开——如何生成高质量的、扎根于知识图谱的训练轨迹。

**教师脚手架设计**。传统做法中，让 LLM 在图谱上探索是一个"发现路径"的过程：模型需要自己决定下一步应该查询哪个关系、扩展到哪些实体。这本质上是一个困难的规划问题，模型可能会走错路、绕远路，甚至生成不存在的路径。Search-on-Graph-R1 的关键创新在于，它不再要求教师模型发现路径，而是提供一条已知的、必然正确的路径——这就是问题对应的 gold SPARQL 查询。

具体来说，给定一个问题和它的标准 SPARQL 查询，研究者们让前沿 LLM 扮演一个"沿着既定路线前进的导航员"。SPARCQL 查询会被解析成一组原子操作，每一步操作对应图谱上的一条边或一个约束。教师模型需要做的不是自己规划，而是正确理解每一步操作并执行它。执行过程中，它调用一个实时的 `Search` 工具，该工具连接真实的 Freebase 服务器，根据操作描述返回图谱上实际存在的实体或关系。由于每次调用都发生在真实的图谱服务器上，返回的结果必然是图谱中真实存在的信息，这就保证了整个轨迹在构造上就是扎根的——不存在幻觉、不存在"图上本不存在的边"。

这个设计有几个精妙之处。首先，轨迹的正确答案保证性来自 SPARQL 查询而非 LLM 的推理能力——查询本身就编码了从主题实体到答案的正确路径，教师模型只需忠实地执行这条路径。其次，所有中间结果都来自真实图谱查询，所以模型学到的是真实的图谱结构和导航模式，而非虚假的"常识推理"。第三，虽然使用的是前沿 LLM 作为教师，但它的角色被简化了，降低了对强大推理能力的依赖，使得能力蒸馏更加高效。

**监督微调阶段**。在这一阶段，研究者们使用上述方法生成的大量轨迹数据对基础 8B 模型进行微调。每个训练样本由问题、相应的 SPARQL 查询、以及完整的执行轨迹组成。模型学习的目标是给定问题和查询，生成与教师轨迹一致的 `Search` 调用序列和最终答案。通过这种方式，模型逐渐学会如何根据 SPARQL 查询的指引在图谱上进行导航。

**强化学习阶段**。SFT 让模型学会了按照给定路径执行导航，但模型还没有学会"自己找到正确路径"。RL 阶段的目标正是弥补这一点。研究者们采用了一种相对简洁的 RL 设置——不使用 LLM 评判器（避免引入额外的推理开销和评判偏差），而是利用 SPARQL 执行结果作为奖励信号：如果模型生成的 SPARQL 查询执行后返回的答案与标准答案一致，就给予正向奖励；否则给予负向奖励。

在 RL 过程中，模型首先生成一个候选的 SPARQL 查询，然后用真实的图谱引擎执行这个查询，观察是否能得到正确答案。这个过程自然地引导模型探索更优的查询结构，因为它必须学会为每个问题生成能导向正确答案的查询——而这需要的正是真正理解问题语义和图谱结构的复合能力。

研究者们还发现了一个值得注意的现象：经过 RL 训练后，模型学会了以比 SFT 初始化更少的 `Search` 调用次数到达答案。这说明 RL 不仅在帮助模型找到正确答案，还在引导模型找到更高效的导航路径——减少不必要的探索步骤，直接沿着最短路径抵达目标。

## 实验与结果

研究者在三个标准的知识图谱问答基准上进行了评估：WebQSP、CWQ 和 GrailQA。这些数据集涵盖了不同复杂度的问答场景，从单跳关系到多跳关系、从简单问句到复杂嵌套问句均有覆盖。

实验结果表明，Search-on-Graph-R1 以 8B 的参数量在所有三个数据集上都取得了显著进步。在 WebQSP 和 CWQ 上，它超越了我们对比中所有冻结权重的前沿 LLM 系统——这意味着即使用 GPT-4o、Claude 等顶级闭源模型以冻结权重的方式（即不针对 KGQA 任务微调）来处理这些问题，Search-on-Graph-R1 依然能取得更优的成绩。在 CWQ 上，Search-on-Graph-R1 更是取得了对比系统中所有方法的最高分，展现了其处理复杂多跳问题的能力。

特别值得强调的是这个系统的简洁性：在推理时，它不需要任何辅助模块（如额外的检索器或验证器）；在训练时，它不依赖 LLM 评判器。完全依靠真实的知识图谱执行结果作为监督和奖励信号。这种简洁性不仅降低了系统复杂度，也使得训练过程更加稳定可靠。

研究者们还进行了消融实验来分析各训练阶段的贡献。结果显示，SFT 和 RL 提供了互补的增益：SFT 让模型学会了基本的图谱导航能力，能够按照给定的查询执行正确的操作；RL 则在这个基础上进一步优化，让模型学会自己生成高质量的查询，并且学会用更少的步骤到达答案。这两个阶段的组合比单独使用任何一个都更有效。

另一个有趣的发现是方法的可迁移性：研究者们在不同模型家族之间进行了迁移实验，结果表明这套训练范式能够跨模型工作——在一个 8B 模型上验证有效后，可以较容易地迁移到其他规模的模型上。这说明方法的核心价值不在于某个特定模型的特性，而在于训练范式本身的合理性。

## 讨论与可借鉴点

Search-on-Graph-R1 展现了一条有价值的路径：如何将大模型在知识图谱上的导航能力高效地压缩到小模型中，同时保证能力的可靠性。传统方法依赖大模型的"涌现能力"来探索图谱，但这导致了高昂的部署成本和对模型规模的依赖。Search-on-Graph-R1 的思路则是"让教师模型按图索骥"，利用已知的正确答案路径来生成可靠、可控的训练数据，再通过 RL 让模型学会自主找到正确路径。这种"脚手架+蒸馏"的范式或许可以启发其他需要复杂推理和结构化决策的任务。

不过，这项工作也存在一些局限性。首先，它依赖于每个问题都有 gold SPARQL 查询，这在标准评测中是现成的，但在实际应用中获取高质量的 SPARQL 标注成本不低。其次，方法目前针对的是 Freebase 这一个知识图谱，迁移到其他知识图谱（如 Wikidata、DBpedia）上可能需要重新训练或适配。第三，虽然 RL 学会了减少搜索调用次数，但对于某些复杂问题，过少的调用可能反而限制了找到正确答案的可能性——如何在效率与成功率之间取得平衡是一个值得探索的问题。

从更宏观的角度看，这项工作提示我们：大模型的能力不一定非要"实时调用"来实现，将特定能力蒸馏到小模型中、再配合可靠的结构化知识源，可能是一种更经济、更可控的方案。在当前大模型推理成本居高不下的背景下，这种思路对于构建可部署的工业级应用具有重要的参考价值。

## 摘要
知识图谱问答（KGQA）需要从主题实体出发，沿着若干关系导航至答案。近期方法通过检索工具提示前沿大语言模型（LLM）在图谱上探索，但由于依赖前沿规模的推理，其部署成本高昂。我们提出了 Search-on-Graph-R1（\sogrone{}），该方法通过监督微调（SFT）和随后的强化学习（RL）将这种导航能力内化到一个紧凑的 8B 模型中。我们的核心思想是，利用每个问题的标准 SPARQL 查询为前沿教师模型搭建脚手架，使教师模型借助实时 \texttt{Search} 工具沿着已知的、包含答案的路径进行遍历，而非自行发现该路径。由于每次调用都在实时 Freebase 服务器上执行，由此产生的轨迹在构建上就扎根于知识图谱本身。在 WebQSP、CWQ 和 GrailQA 数据集上，\sogrone{} 以 8B 的参数量超越了我们对比中所有冻结的前沿 LLM 系统，并在 CWQ 上取得了我们所对比系统中所有系统的最优成绩。它在推理时不使用任何辅助模块，在训练时也不使用 LLM 评判器。对每个训练阶段进行单独分析表明，SFT 和 RL 带来了互补的增益，我们的方法可在不同模型家族之间迁移，且 RL 学会了以比其 SFT 初始化更少的 \texttt{Search} 调用次数到达答案。

## Abstract
Knowledge graph question answering (KGQA) requires navigating from topic entities to an answer several relations away. Recent methods prompt a frontier LLM to explore the graph through a retrieval tool, but their reliance on frontier-scale inference makes them costly to deploy. We present Search-on-Graph-R1 (\sogrone{}), which internalizes this navigation into a compact 8B model through supervised fine-tuning (SFT) followed by reinforcement learning (RL). Our central idea is to scaffold a frontier teacher with each question's gold SPARQL query, so the teacher traverses a known answer-bearing path with a live \texttt{Search} tool rather than having to discover the path itself. Since every call executes against a live Freebase server, the resulting trajectories are grounded in the knowledge graph by construction. On WebQSP, CWQ, and GrailQA, \sogrone{} at 8B surpasses every frozen frontier-LLM system in our comparison and posts the strongest results on CWQ of any system we compare against. It does so using no auxiliary module at inference and no LLM judge during training. Isolating each training stage shows that SFT and RL contribute complementary gains, our approach transfers across model families, and RL learns to reach answers in fewer \texttt{Search} calls than its SFT initialization.
