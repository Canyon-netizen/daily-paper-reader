## TL;DR

大模型推理时产生的长思维链中充斥着冗余推导与无效绕行，直接压缩会损害准确率。现有同策略自蒸馏方法从冗长基模型起步时存在"初始化瓶颈"——KL 损失被施加在已退化的前缀上，教师只能做局部修补。本文提出 BIRD 两阶段方法：先用简洁指令引导基础模型采样干净轨迹，经 prompt-switch SFT 将指令式简洁转化为默认行为，再用此暖启动模型执行 reverse-KL 蒸馏。在 Qwen3-8B 上实现了 92.0% 的 MATH-500 准确率，同时将平均响应长度从 3,099 token 压缩至 1,115 token，揭示了前缀支持（prefix support）才是高效推理蒸馏的核心设计因素。

## 研究背景与动机

大推理模型（Large Reasoning Model）通过生成长链式思维（Chain-of-Thought）轨迹展现出了强大的数学与代码推理能力，但这些轨迹的计算开销远超必要。以 Qwen3-8B 为例，其在 MATH-500 上的平均响应长度高达 3,099 token，其中相当一部分计算被消耗在重复的自我验证、多余的推导步骤以及最终答案根本不会涉及的绕行上。如何在保持甚至提升准确率的前提下压缩这些冗余推理轨迹，成为推理效率优化的关键问题。

一个直观的思路是对已有长轨迹进行蒸馏压缩。现有研究提出了多种同策略自蒸馏（On-Policy Self-Distillation, OPSD）方法，其核心做法是让模型在自身采样的前缀上匹配一个"简洁版自己"——即用简洁指令引导教师模型产生更凝练的下一个 token 预测，学生则在此前缀分布上向教师学习。这类方法的代表如 CRISP，通过 reverse-KL 散度在推理轨迹的每一步施加局部监督，引导模型逐渐习惯更简洁的推理模式。

然而，本文作者敏锐地识别出了这一范式的一个根本性缺陷：**初始化瓶颈**（initialization bottleneck）。具体而言，OPSD 的 KL 监督是前缀局部的——损失只在学生当前 rollout 所到达的前缀 $y_{<t}$ 上计算，教师也仅在这些前缀条件下提供 next-token 的目标。当训练从一个冗长、啰嗦的基模型起步时，学生在 Stage 1 访问的前缀本身就带有大量噪声、冗余内容甚至偏离正确思路的中间步骤。在这样的退化语境下，简洁教师只能在前缀末尾做微弱的局部修正，而学生整体的低效探索模式并未得到根本性改善。这形成了一个恶性循环：坏前缀产生弱纠错，弱纠错导致仍产生坏前缀，最终压缩的上限被初始化质量牢牢锁死。

本文的核心研究问题因此浮出水面：如何让学生在同策略蒸馏过程中访问到更适合被压缩的、干净且高效的前缀分布？这不仅是教师构造的问题，更是一个**前缀支持**（prefix support）的设计问题。

## 方法

BIRD 的设计哲学是将分布匹配解耦为两个互补的阶段：**离线的 bootstrap 暖启动**与**在线的 refinement 精炼**。这种两阶段框架的直觉在于，推理压缩的难点不在于"如何压缩"，而在于"从什么样的基础出发压缩"——只有当学生采样的前缀本身已经足够干净时，reverse-KL 目标的局部监督才能真正发挥作用。

### 第一阶段：静态暖启动（Bootstrap）

第一阶段的目标是彻底改变学生将访问的前缀分布，使其从冗长退化转为简洁高效。做法分为三步：

**简洁采样**：对训练集中的每个问题 $x$，用基模型 $\pi_{\theta_0}$ 在简洁指令 $c$ 的条件下采样一条解答轨迹 $y_i \sim \pi_{\theta_0}(\cdot \mid x, c)$。这里的简洁指令可以是类似"请简洁地回答"这样的短句，其作用是激活模型自身的简洁推理能力，但不希望在推理时永久依赖这个额外提示。

**正确性过滤**：过滤是 BIRD 保证训练质量的关键。保留那些最终答案与ground truth一致的唯一轨迹，形式化为：
$$D_{\text{filtered}} = \{(x, \tilde{y}) \mid \text{answer}(\tilde{y}) = \text{GT}(x)\}$$

每道题仅保留一条正确轨迹，并截断至 $T_{\text{SFT}} = 2048$ token。这种硬过滤确保了后续学习的轨迹本身是正确的、只是表达更简洁，而非通过噪声或错误路径强行压缩。

**Prompt-Switch SFT**：这是最关键、也最巧妙的一步。标准的 SFT 直接在 $(x, c)$ 条件下学习 $\tilde{y}$，模型学会的是"在有简洁指令时才简洁"。BIRD 采取的策略是：用带指令的 prompt 生成轨迹，但在训练时去掉指令，仅在原始任务提示 $x$ 下做 one-epoch 的 LoRA SFT。损失函数为：
$$\mathcal{L}_{\text{SFT}} = -\mathbb{E}_{(x, \tilde{y}) \sim D_{\text{filtered}}} \left[ \sum_{t} \log \pi_{\theta}(\tilde{y}_t \mid x, \tilde{y}_{<t}) \right]$$

这一"prompt-switch"操作的效果是深远的：模型在生成阶段接触到的是简洁轨迹的分布特征（因为训练数据本身就是简洁采样的结果），但在学习阶段是在无额外提示的自然条件下拟合这些轨迹的分布。由此，指令引发的简洁性被内化为模型的默认行为——它不再需要"被提醒要简洁"，而是自然而然地倾向于生成凝练的推理步骤。

### 第二阶段：在线精炼（On-Policy Refinement）

从 warm-start 模型 $\pi_{\theta_{\text{SFT}}}$ 出发，进入标准 OPSD 的迭代循环。与冷启动 OPSD 的关键区别在于：此时学生采样得到的前缀已经具备较高的质量——它们是简洁暖启动模型 rollouts 的产物，而非原始冗长基模型的退化产物。

每 $M$ 步，教师参数 $\bar{\theta}$ 从学生参数 $\theta$ 更新一次（stop-gradient）。对于每个采样得到的轨迹前缀 $y_{<t}$，reverse-KL 目标为：
$$\mathcal{L}_{\text{KL}} = D_{\text{KL}}\left(\pi_{\theta}(\cdot \mid x, y_{<t}) \parallel \pi_{\bar{\theta}}(\cdot \mid x, c, y_{<t})\right)$$

reverse-KL 相比 forward-KL 的选择同样经过审慎考量：它倾向于让学生覆盖教师的模式（即"简洁地推理"），而非让学生为教师不屑探索的冗余路径分配概率，这与压缩目标高度一致。

值得注意的是，KL 计算被限制在每条轨迹的前 $T_{\text{KL}} = 1024$ token 上，这确保了学习信号集中在轨迹中信息密度最高的早期推理阶段。

### 支持放置原则（Support-Placement Principle）

从整体上审视 BIRD 的设计逻辑，可以提炼出一个核心原则：**OPSD 的有效性不仅取决于教师如何构造，更取决于教师被查询时所处的前缀分布**。这个看似简单的观察对领域具有重要的范式意义——它将研究者的注意力从"如何造一个更好的教师"引导到"如何造一个更好的前缀分布"。BIRD 的两阶段设计正是这一原则的具体实现：第一阶段改善了 rollout 诱导的前缀支持（prefix support），第二阶段才在此基础上高效地进行分布匹配。

## 实验与结果

实验在 Qwen3 系列模型（1.7B、4B、8B）上进行，训练数据为 DAPO-Math-17k-dedup，评测基准包括 MATH-500、AIME 2024 和 AIME 2025。对比基线涵盖仅推理时使用简洁指令（Concise）、论文复现的 CRISP 冷启动方法、以及多种消融变体。

衡量指标的设计体现了作者对精度-效率权衡的深入思考。单纯的准确率无法反映压缩收益，单纯的长度削减也无法保证质量。为此引入 **Token Efficiency (TE)**：
$$\text{TE} = \frac{\text{Accuracy}}{\ln(\text{Length})}$$

采用对数长度而非线性长度，隐含的假设是压缩的边际收益递减——将 100 token 压缩到 50 token 比将 1000 token 压缩到 950 token 更具实际价值。每 25 步保存 checkpoint，报告每个基准上 TE 最高的模型状态。

**主结果**（Table 1）呈现了令人信服的结论。在 9 个（模型规模 × 基准）的评测单元中，BIRD 在 8 个上取得了最高的 TE，且优势随模型规模增大而扩大。以 Qwen3-8B 为例：MATH-500 准确率从基线 86.2% 提升至 92.0%（+5.8 点），同时平均响应长度从 3,099 token 降至 1,115 token（压缩约 64%）。这意味着模型不仅变得更简洁，思考质量也实质提升——简洁并非以牺牲正确性为代价。AIME 2024 的结果进一步印证：准确率提升 5.0 点，响应长度反降 18%，实现了精度与效率的双赢。

## 讨论与可借鉴点

BIRD 最重要的理论贡献在于它提出了 **support-placement principle**：对于 on-policy 自蒸馏方法，前缀支持的位置（即学生在训练中实际访问到什么样的前缀分布）比教师构造的细节更为关键。这一原则将领域研究从"如何造教师"引导到"如何造前缀分布"，为后续工作开辟了新的设计空间。

从工程视角看，BIRD 的实用性令人印象深刻。它不依赖外部强大的教师模型，不引入额外的推理开销（Stage 1 的 prompt-switch SFT 仅需一次性的离线训练），且仅需轻量级的 LoRA 适配。数据构造也极为简洁——每题仅采样一条 rollout，每题仅保留一条正确轨迹。相比于需要大量超参调优或复杂训练管道的方案，BIRD 的工程复杂度处于较低水平。

然而，这项工作也存在若干局限。首先是 **对 ground truth 标签的隐性依赖**：Stage 1 的正确性过滤需要每个训练样本有标准答案，这在具有自动评测脚本的数学基准上不成问题，但限制了方法在开放式生成或无结构化标签场景的迁移。其次是 **对基模型指令跟随能力的依赖**：如果基模型本身对"简洁"指令的理解和执行能力较弱，第一阶段采样的轨迹可能既不简洁也不正确。此外，压缩比例受限于训练数据本身的推理复杂度——对于极其困难的题目（如 AIME 高分区），完全压缩推导步骤可能损失必要的中间推理。

对于推理模型蒸馏这一研究方向，BIRD 提供了几点值得深思的启示。**第一**，在追求更强的 [[distillation]] 技术之前，应先审视作为蒸馏起点的前缀分布是否健康。**第二**，指令诱导的行为与默认行为之间存在一条鸿沟，prompt-switch 这种看似简单的设计实际上完成了一次关键的能力迁移。**第三**，精度-效率的帕累托前沿可以通过改变初始条件（而非仅调整训练目标）来实质性拓展。BIRD 的核心洞察——关注 prefix support 而非仅关注教师构造——有可能成为后续推理压缩研究的重要出发点。

## 摘要
大型推理模型通常通过长链式思考（CoT）轨迹来解决问题，然而这些计算中很大一部分被花费在冗余推导、重复的自我验证以及对最终答案没有帮助的绕行上。现有的同策略自蒸馏方法通过让学生模型在前缀上匹配其自身的简洁副本来降低这种成本，这些前缀是从学生模型自身的 rollout 中采样得到的。我们表明该目标存在一个初始化瓶颈。由于监督仅施加于已访问的前缀，从冗长的基模型进行训练会将 KL 损失置于那些往往嘈杂、冗余或已偏离正轨的上下文之上。在这些区域中，简洁的教师只能提供局部修正，而学生模型则继续探索那些高效推理者本应规避的轨迹。在本文中，我们提出了 BIRD（自举迭代自推理蒸馏），这是一种两阶段的自推理蒸馏方法，在同策略训练之前先改善 rollout 分布。BIRD 首先在简洁性指令下从基模型采样简洁解答，仅保留答案正确的轨迹，并执行轻量级的提示切换 SFT 步骤。这些轨迹是在简洁性指令下生成的，但在原始任务提示下被学习，从而将由指令引发的简洁性转化为默认的推理行为。从这一暖启动模型出发，BIRD 再使用简洁的自教师进行同策略 reverse-KL 蒸馏，此时所面对的前缀更为干净、也更具信息量。在 Qwen3 系列模型上，BIRD 在 MATH-500 和 AIME 基准上实现了比提示方法和冷启动同策略蒸馏更强的精度-效率权衡。在 Qwen3-8B 上，它将 MATH-500 准确率从 86.2% 提升至 92.0%，同时将平均响应长度从 3,099 个 token 压缩至 1,115 个 token。这些结果凸显了前缀支持作为高效推理蒸馏中核心因素的重要地位。

## Abstract
Large reasoning models often solve problems through long chain-of-thought (CoT) traces, yet much of this computation is spent on redundant derivations, repeated self-verification, and detours that do not improve the final answer. Existing on-policy self-distillation methods reduce this cost by matching a student model to a concise copy of itself on prefixes sampled from the student's own rollouts. We show that this objective has an initialization bottleneck. Since supervision is applied only to visited prefixes, training from a verbose base model places the KL loss on contexts that are often noisy, redundant, or already off track. In such regions, a concise teacher can provide only local corrections, while the student continues to explore trajectories that an efficient reasoner should avoid. In this paper, we propose BIRD(Bootstrapped Iterative Self-Reasoning Distillation), a two-stage self-reasoning distillation method that improves the rollout distribution before on-policy training. BIRD first samples concise solutions from the base model under a brevity instruction, keeps only answer-correct traces, and performs a lightweight prompt-switch SFT step. The traces are generated with the brevity instruction but learned under the original task prompt, turning instruction-induced conciseness into a default reasoning behavior. Starting from this warm model, BIRD then applies on-policy reverse-KL distillation with a concise self-teacher, now on cleaner and more informative prefixes. Across Qwen3 series models, BIRD achieves a stronger accuracy-efficiency trade-off than prompting and cold-start on-policy distillation on MATH-500 and AIME benchmarks. On Qwen3-8B, it improves MATH-500 accuracy from 86.2% to 92.0% while reducing the average response length from 3,099 to 1,115 tokens. These results highlight prefix support as a central factor in efficient reasoning distillation.

## 1. 核心问题与研究动机

大推理模型（如 Qwen3、DeepSeek-R1 系列）虽然通过长链思维（CoT）展现了强大推理能力，但其推理轨迹通常包含数千 token，其中充斥着**冗余推导、重复自我验证与无效绕行**，这些冗余计算对最终答案几乎无贡献，却显著增加了推理成本。

现有 **on-policy 自蒸馏（OPSD）** 方法（如 CRISP）通过让学生模型在自身采样轨迹的前缀上匹配"简洁版自身"的输出来压缩推理。然而作者识别出一个关键缺陷——**初始化瓶颈（cold-start prefix-support bottleneck）**：

- OPSD 的 KL 监督是**前缀局部**的：loss 仅作用于学生当前采样轨迹所到达的前缀 $y_{<t}$，教师只在这些前缀上提供 next-token 目标。
- 当训练从冗长的基模型起步时，学生访问的前缀本身已带有噪声、冗余或偏离正轨。
- 此时简洁教师只能在该退化上下文上做**局部纠错**，无法改变学生整体的低效探索模式。
- 这种"坏前缀 → 弱纠错 → 仍坏前缀"的循环限制了可达的压缩上限。

因此，本文的核心问题是：**如何让学生在 on-policy 蒸馏中访问到更适合被压缩的、干净且高效的前缀分布？**

## 2. 方法论：BIRD 两阶段框架

### 2.1 总体思路

BIRD 将分布匹配解耦为**离线 bootstrap + 在线 refinement** 两个阶段：

- **Stage 1（Static Bootstrap）**：用基模型在简洁指令下采样并经正确性过滤后做一次轻量 prompt-switch SFT，把"指令引发的简洁性"转化为模型的默认行为，同时改变学生将访问的前缀分布。
- **Stage 2（Dynamic Refinement）**：从 warm-start 模型出发，沿用相同的前缀局部 reverse-KL 目标，但此时教师的 next-token 目标落在更干净、更具信息量的前缀上。

### 2.2 关键技术与公式

**分布匹配的统一视角**：
$$\min_{\theta} D\left[\pi_{\theta}, \pi_{\text{target}}\right]$$
不同方法差异在于 $\pi_{\text{target}}$ 的构造方式与 loss 实际评估位置。

**OPSD 的前缀局部目标**（公式 3）：
$$L(\theta) = \mathbb{E}_{x \sim D,\, y \sim \pi_{\theta}(\cdot|x)} \left[ \sum_{t} D_{\mathrm{KL}}\!\left(q_t \,\|\, p_t\right) \right]$$
其中：
- $q_t = \pi_{\theta}(\cdot \mid x, y_{<t})$ 为学生当前策略
- $p_t = \pi_{\bar{\theta}}(\cdot \mid x, c, y_{<t})$ 为带简洁指令 $c$ 的 stop-gradient 教师

**Stage 1 数据构造**：
$$D_{\text{filtered}} = \{(x,\, y) \mid \text{answer}(y) = \text{GT}(x)\}$$
每个问题仅采样一条简洁 rollout，用答案正确性做硬过滤，截断到 $T_{\text{SFT}} = 2048$ token。

**Prompt-Switch SFT**：trace 用 $(x+c)$ 生成，但训练目标仅在 $x$ 下做 one-epoch LoRA SFT，把指令式简洁固化为默认行为。

**Stage 2 KL 计算限制**：仅在每条 rollout 的前 $T_{\mathrm{KL}} = 1024$ token 上计算 KL，教师每 $M$ 步由学生参数刷新一次（stop-gradient）。

### 2.3 算法流程（Algorithm 1）

```
Stage 1: Bootstrap Concise Prefix Support
  for each (x_i, GT_i) ∈ D:
      y_i ~ π_θ0(·|x_i, c)
      if answer(y_i) = GT_i:
          ỹ_i ← Truncate(y_i, T_SFT)
          D_filtered ← D_filtered ∪ {(x_i, ỹ_i)}
  θ_SFT ← LoRA-SFT(θ_0, D_filtered; (x_i+c) → x_i)
  θ ← θ_SFT

Stage 2: Warm-Start On-Policy Self-Distillation
  θ̄ ← StopGrad(θ)
  for k = 1, 2, ..., K:
      if k mod M = 0: θ̄ ← StopGrad(θ)
      sample batch B ⊂ D
      for each x_i ∈ B:
          y_i ~ π_θ(·|x_i)
          T_i ← min(|y_i|, T_KL)
          ℓ_{i,t} ← D_KL(π_θ(·|x_i, y_{i,<t}) ∥ π_θ̄(·|x_i, c, y_{i,<t}))
      L_B ← |B|^{-1} Σ L_i
      Update θ with ∇_θ L_B
  return π_θ*
```

### 2.4 核心设计原则

提出 **support-placement principle**：OPSD 的有效性不仅取决于简洁教师如何构造，更取决于教师被查询时所处的前缀分布（rollout-induced prefix support）。

## 8. 不足与局限

- **对真实标签的依赖**：Stage 1 需要 ground truth 做正确性过滤，限制了在无标签或弱监督场景的应用；尽管 ground truth 仅用于二元过滤而非作为模型输入，但仍是隐性数据假设。
- **对简洁指令跟随能力的依赖**：Stage 1 的 trace 质量取决于基模型能否理解"简洁"指令；较小或微调较少的模型可能产生低质简洁 trace，warm-start 效果打折。
- **基准覆盖偏窄**：仅评测 MATH 类数学推理（MATH-500、AIME 2024/2025），未覆盖代码、常识、开放域 QA 等其他推理类型；论文声称的"压缩推理"结论在非数学场景下泛化性未知。
- **Checkpoint 选择偏差**：报告 TE 最高的 checkpoint，可能掩盖训练后期过拟合或不稳定；缺少与"最终 checkpoint"或"固定训练步数"对比的公平性分析。
- **算力与训练成本披露不充分**：仅给出 8×A800，未报告单次完整 BIRD 训练的总耗时、显存峰值、Stage 1 SFT 与 Stage 2 OPSD 的相对开销。
- **LoRA 而非全参数微调**：所有方法均用 LoRA 适配，未与全参数微调（如 GPT-OSS、QwQ 等基线对比）验证是否结论对参数规模与微调方式敏感。
- **Stage 2 KL 仅作用于前 1024 token**：这一截断虽节省算力，但可能在长推理问题上过早丢弃关键监督信号，缺乏对 $T_{\mathrm{KL}}$ 取值的敏感性分析。
