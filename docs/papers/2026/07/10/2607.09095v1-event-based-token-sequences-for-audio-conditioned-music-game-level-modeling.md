## 摘要
音乐游戏关卡的程序化生成是一个令人兴奋但具有挑战性的问题，因为关卡必须将音乐结构转化为定时游戏事件的交互序列。大多数现有方法通过基于帧的表示来构建这一任务，将音频划分为统一的时间网格，并在每一帧预测事件。这使得游戏事件隐式地分布在许多帧之间。因此，很难描述事件级的时间关系以及人工创作关卡中存在的更长范围的结构。我们将程序化生成作为一个实践场景，用于研究音乐线索如何映射到交互式事件序列。受基于事件的符号音乐建模的启发，我们提出了一种令牌级序列建模框架，将关卡生成视为多模态序列到序列问题。以音频片段和关卡元数据为条件，模型生成一个交替排列游戏事件令牌和节拍位移令牌的令牌序列。这显式地表示了动作及其在节拍空间中的相对时间关系。基于这一建模框架，我们构建了一个 Transformer 模型。该模型在事件级评估下优于代表性的基于帧的基线方法，并且能够系统性地分析音频如何在元数据条件之外进一步支持节奏对齐的事件预测。

## Abstract
Procedural generation of music game levels is an exciting yet challenging problem, as levels must translate musical structure into interactive sequences of timed gameplay events. Most existing approaches formulate this task by frame-based representations, dividing audio into uniform time grids and predicting events at each frame. This makes gameplay events implicit across many frames. As a result, it is hard to describe event-level timing relations and longer-range structure found in human-authored levels. We use procedural generation as a practical setting to study how musical cues map to interactive event sequences. Inspired by event-based symbolic music modeling, we propose a token-level sequence formulation that casts level generation as a multimodal sequence-to-sequence problem. Conditioned on an audio excerpt and level metadata, the model generates a token sequence alternating gameplay-event and beat-shift tokens. This explicitly represents actions and their relative timing in beat space. Based on this formulation, we build a Transformer model. It outperforms representative frame-level baselines under event-level evaluation. It also enables systematic analysis of how audio supports rhythm-aligned event prediction beyond metadata conditioning.

## 1. 核心问题与研究动机

音乐游戏关卡的程序化生成（PCG）需要将连续音乐信号映射为离散、可交互的时序事件序列，这对 MIR 领域具有基础研究价值。现有主流方法采用**基于帧（frame-based）的表示**：将音频切分为均匀时间网格，在每一帧进行二分类（onset 检测），再组合为事件。该范式存在三大固有缺陷：

- **事件级时间关系隐式化**：事件散落在多帧中，事件之间的相对时序需从密集帧级预测中推断；
- **长程结构难以刻画**：人工谱面所具备的节奏一致性、乐句结构、难度递进等性质被帧级建模分散；
- **音乐—事件对齐弱**：依赖外部 beat-aligned 引导，无法显式表达 beat-relative timing。

本文将 PCG 视为研究"音乐线索到交互事件序列映射"的实验平台，主张借鉴符号音乐建模中**事件级（event-based）**表示的成功经验，重新设计关卡生成的时间表征。

## 2. 方法论

### 2.1 核心思想
将关卡建模视为**多模态 seq2seq 任务**：以音频片段 $a$ 与关卡元数据 $m$ 为条件，自回归生成由 **beat-shift 令牌**与**游戏事件令牌**交替排列的离散序列。

条件分布形式化为：

$$p(y \mid x, m) = \prod_{i=1}^{N} p(y_i \mid y_{<i}, x, m)$$

其中 $x = f_{\text{audio}}(a)$ 为音频编码器输出，$y$ 为目标令牌序列。

### 2.2 事件级表征设计（simai maidata 风格）

- **节拍空间（beat space）**：所有时间表达均以节拍为基本单位，每拍细分为 $U=8$ 个时间单位；
- **beat-shift 令牌**：表示相邻事件间的相对位移量 $k$，对应时间增量 $\Delta b = k/U$；
- **事件词汇表**：5 类动作——`tap`、`hold`（start/end 对）、`slide`、`double`、`break`，外加 `<pad>`、`<s>`、`</s>`、`<unk>`；
- **构造流程**（三步）：
  1. 将 beat-aligned 的原始谱面解析为按节拍排序的事件序列；
  2. 事件间相对位移用 beat-shift 令牌编码，事件语义用事件令牌编码；
  3. 交替拼接形成线性令牌序列，可由确定性规则无损重建为谱面。

相较于帧级表示的优点：(i) 事件中心；(ii) 显式表达事件—事件时间关系；(iii) 操作于 beat space，保留音乐语义；(iv) 避免密集网格的空洞符号；(v) 规则化映射，无需峰值检测/平滑启发式。

### 2.3 模型架构（Encoder–Decoder Transformer）

| 模块 | 关键设计 |
|------|----------|
| **音频编码器** | 预训练 Whisper-base 或 MERT，输出约 50 Hz 帧级声学表示 $h = (h_1,\ldots,h_T)$，不做冻结，从第一步起联合训练 |
| **元数据嵌入** | BPM 与 skill rating 经独立线性层投影；difficulty tier（5 类）经可学习嵌入；三者拼接为全局向量 $m_{\text{enc}}$ |
| **融合策略** | 将 $m_{\text{enc}}$ 广播到所有编码器时间步并与 $h_t$ 拼接，得到融合表征 $h'_t = [h_t; m_{\text{enc}}]$ |
| **解码器** | 12 层 Transformer，hidden=768，FFN=2048，8 头；因果自注意力 + 对编码器帧级表征的交叉注意力；teacher-forcing 交叉熵，label smoothing=0.05 |
| **正则化** | 元数据/文本 dropout=0.2；所有 decoder dropout 设为 0 |
| **推理** | 贪心解码或 beam size=5 + length normalization；硬终止约束：累计 beat-shift 超过输入片段总节拍数时强制截断 |

## 3. 实验设计

### 3.1 数据集
- 来源：商业音乐游戏 **maimai** 的谱面（仅用于学术研究，原始资源不发布）；
- 规模：**4,187 谱面 / 1,018 首曲目**，按曲目级 70/15/1 5 划分；
- 片段级样本：21,595 / 2,808 / 2,669（train/valid/test），每片段 80 beats；
- 词汇统计：平均 120–260 tokens/序列；beat-shift 占 ~54%，事件占 ~46%；
- 数据合规：仅发布非可逆的示意性 token 序列与完整转换/训练代码。

### 3.2 评测协议与指标

- **主指标：Event-level F1**（多类事件级 F1，时间容差 $1/8$ beat）；
- **辅助指标：Frame-level Onset F1**（仅作为帧级基线内部参考）；
- **生成退化诊断**：(i) extreme-density rate（8-beat 窗口事件数 > 99% 分位阈值 $K=40$ 的比例）；(ii) loop-collapse rate（连续重复模式长度 $\geq L=16$ 且重复 $\geq R=4$ 次的比例）。

### 3.3 对比方法
- **外部基线**：
  - **DDC**（Dance Dance Convolution, Donahue et al. 2017）：CNN–RNN 帧级分类；
  - **GeneLive!**（Takada et al. 2023）：含 beat-synchronous 引导的帧级方法；
  - 二者均被适配为 6 类（none + 5 类事件）帧级分类器，经时序平滑 + 局部峰值检测重建事件。
- **内部消融变体**：
  - Whisper (full) / MERT；
  - Whisper (zero-meta)：去除元数据条件；
  - zero-audio：完全去除音频输入。

### 3.4 Audio Contribution Score（ACS）
为分离音频相对元数据/序列先验的独立贡献，提出：

$$\text{ACS} = \frac{S_{\text{true}} - S_{\text{shuf}}}{S_{\text{forced}} - S_{\text{shuf}}}$$

- $S_{\text{true}}$：正确音频下的标准自回归得分；
- $S_{\text{shuf}}$：音频在样本间随机打乱（破坏对齐）的得分，反映元数据与自回归先验的贡献；
- $S_{\text{forced}}$：teacher-forced 上界，去除自回归暴露误差。

ACS ≈ 0 表示性能主要来自非音频因素；越接近 1 表示越依赖音频—事件对齐。

## 6. 主要结论与发现

1. **方法有效性**：在所有 5 个难度档位上，本文模型 Event-F1 均显著超越两种帧级基线（平均 0.527 vs. DDC 0.254、GeneLive! 0.298），验证事件级 token 化对音乐—事件对齐的建模优势。
2. **音频—元数据分工**：
   - 音频主要提供**局部时序对齐**线索（事件放置的 beat-relative 精度）；
   - 元数据（BPM、难度）主要调控**高层结构倾向**（密度、节奏型选择）。
   - Whisper（full）ACS=0.58，去除元数据后 zero-meta 的 ACS 升至 0.67，验证元数据减少时音频承担更大相对权重。
3. **音频编码器选择**：Whisper（≈20–25 ms/帧）优于 MERT（≈40–50 ms/帧），表明更高的时间分辨率在固定节拍容差下提供更细粒度的事件放置线索。
4. **零音频下限**：zero-audio 性能降至 0.266（与帧级基线相当或更低），证明真正的事件放置仍需音频信号；元数据+自回归先验不足以独立支撑事件级重建。
5. **退化可控**：Whisper（full）下 extreme-density=2.1%、loop-collapse=0.4%，数值上较低；但 zero-audio 时分别升至 5.9% 与 4.3%，再次印证音频对节奏稳定性的贡献。

## 7. 优点

- **表示层面的根本性改进**：从帧级到事件级的范式迁移，使"动作—相对时序"成为一等公民，类比于 REMI/PerformanceRNN 在符号音乐生成中的成功，论证充分；
- **音乐—游戏领域桥接的明确语义**：beat-shift 令牌使节拍空间成为建模基本单位，与 maimai 谱面创作惯例完全一致，无须有损转换到绝对时间；
- **统一的事件级评测协议**：将帧级基线也通过平滑+峰值检测映射到事件序列，使得跨范式比较在同一度量下进行，避免了"用 onset F1 模糊胜负"的常见陷阱；
- **ACS 指标的提出**：在自回归生成场景下，首次给出形式化方法剥离元数据/序列先验与音频的边际贡献，方法论上具有推广价值；
- **数据合规处理严谨**：原始资源不发布、仅发布非可逆示例 + 完整代码，平衡学术可复现性与版权约束；
- **跨难度档位分析**：揭示性能随难度上升的衰减规律，启发了后续关于词汇表丰富度与人体工学约束的研究方向。

## 8. 不足与局限

- **数据集单一性**：仅使用 maimai 一个游戏、单一语言区域曲目，未覆盖 osu!、DDR、SDVX、Arcaea 等其他节奏游戏的谱面格式差异，方法的跨游戏泛化能力未验证；
- **空间属性缺失**：当前 token 词汇仅建模"事件类型 + 时间"，**lane / 坐标等位置信息被显式排除**；这意味着方法无法直接生成可玩谱面，仅完成第一阶段（事件存在+类型）预测；
- **物理/人体工学约束未建模**：高 BPM 下出现物理冲突动作（5.5 节），说明纯符号序列建模不感知设备物理约束；
- **词汇粒度不足**：高难度档位下"复杂交互模式"覆盖不足，作者已自承词汇表天花板是性能瓶颈；
- **音频—乐器锚定弱**：模型对具体乐器成分的跟随能力有限，表现为事件与特定声部关联不清，与 zero-meta 实验共同指向音频表征的乐器级分辨力问题；
- **ACS 的数值稳定性**：zero-audio 条件下分母接近 0，ACS 不可计算；方法对长尾退化情形敏感；
- **可复现性缺口**：无 GPU 类型/数量/训练时长/能耗报告；未提供多随机种子的统计显著性检验；尽管发布了代码，外部复现仍存在工程不确定性；
- **评测偏自动化**：缺少人工可玩性评分、专家谱师评价或玩家感知实验，无法证明生成谱面在实际游玩体验上达到人工谱面水准；
- **长程上下文受限**：当前片段 80 beats 的固定窗口，难以建模跨乐句的长程难度曲线与编排叙事。
