## 摘要
大型推理模型通常通过长思维链（CoT）轨迹来解决问题，然而大量计算耗费在冗余推导、重复自我验证以及无法改善最终答案的迂回路径上。现有的同策略自蒸馏方法通过让学生模型在自身 rollout 采样的前缀上匹配其简洁副本，从而降低这种开销。我们表明该目标存在初始化瓶颈。由于监督仅施加于已访问的前缀上，从冗长的基模型进行训练会将 KL 损失置于那些通常嘈杂、冗余或已偏离正轨的上下文上。在这些区域中，简洁教师只能提供局部修正，而学生则会持续探索那些高效推理者本应避免的轨迹。本文提出 BIRD（Bootstrapped Iterative Self-Reasoning Distillation，自举迭代自推理蒸馏），一种在同策略训练之前改进 rollout 分布的两阶段自推理蒸馏方法。BIRD 首先在简洁性指令下从基模型采样简洁解，仅保留答案正确的轨迹，并执行轻量级的提示切换 SFT 步骤。这些轨迹是在简洁性指令下生成的，但在原始任务提示下学习，从而将指令诱导的简洁性转变为默认的推理行为。从该热启动模型出发，BIRD 随后在更清晰、信息量更丰富的前缀上应用同策略反向 KL 蒸馏，并以简洁的自教师作为指导。在 Qwen3 系列模型上的实验表明，BIRD 在 MATH-500 和 AIME 基准上相较于提示方法和冷启动同策略蒸馏实现了更优的精度-效率权衡。在 Qwen3-8B 上，它将 MATH-500 的精度从 86.2% 提升至 92.0%，同时将平均响应长度从 3,099 个 token 缩短至 1,115 个 token。这些结果凸显了前缀支撑作为高效推理蒸馏中的核心因素。

## Abstract
Large reasoning models often solve problems through long chain-of-thought (CoT) traces, yet much of this computation is spent on redundant derivations, repeated self-verification, and detours that do not improve the final answer. Existing on-policy self-distillation methods reduce this cost by matching a student model to a concise copy of itself on prefixes sampled from the student's own rollouts. We show that this objective has an initialization bottleneck. Since supervision is applied only to visited prefixes, training from a verbose base model places the KL loss on contexts that are often noisy, redundant, or already off track. In such regions, a concise teacher can provide only local corrections, while the student continues to explore trajectories that an efficient reasoner should avoid. In this paper, we propose BIRD(Bootstrapped Iterative Self-Reasoning Distillation), a two-stage self-reasoning distillation method that improves the rollout distribution before on-policy training. BIRD first samples concise solutions from the base model under a brevity instruction, keeps only answer-correct traces, and performs a lightweight prompt-switch SFT step. The traces are generated with the brevity instruction but learned under the original task prompt, turning instruction-induced conciseness into a default reasoning behavior. Starting from this warm model, BIRD then applies on-policy reverse-KL distillation with a concise self-teacher, now on cleaner and more informative prefixes. Across Qwen3 series models, BIRD achieves a stronger accuracy-efficiency trade-off than prompting and cold-start on-policy distillation on MATH-500 and AIME benchmarks. On Qwen3-8B, it improves MATH-500 accuracy from 86.2% to 92.0% while reducing the average response length from 3,099 to 1,115 tokens. These results highlight prefix support as a central factor in efficient reasoning distillation.

## 一、核心问题与研究动机

### 1.1 研究背景
- 大型推理模型（如 Qwen3 系列、DeepSeek-R1）通过长思维链（Chain-of-Thought, CoT）解决复杂数学问题，推理轨迹常达数千 token。
- 长 CoT 中存在大量**冗余计算**：重复推导、反复自我验证（self-verification）、与最终答案无关的迂回路径。
- **推理压缩（Reasoning Compression）** 旨在缩短推理长度同时保持甚至提升准确率，是高效部署推理模型的关键。

### 1.2 现有方法分类
| 方法类型 | 代表工作 | 核心思想 |
|---|---|---|
| 训练无关（Prompting） | Concise Prompting | 推理时施加简洁指令控制 |
| RL 类 | L1、DiPO、SwAP、Leash | 引入长度敏感奖励 |
| SFT 类 | TokenSkip、V-Skip、CoT-Valve、CtrlCoT | 模仿压缩轨迹 |
| 同策略自蒸馏（OPSD） | CRISP、TIP、FiRe-OPD | 模型自身充当简洁教师 |

### 1.3 关键发现：冷启动前缀支撑瓶颈
- OPSD 的优化目标是**前缀局部（prefix-local）** 的：学生采样 rollout，KL 损失仅在该 rollout 已访问的前缀 $y_{<t}$ 上计算。
- 当从**冗长的基模型**直接开始训练时，学生访问的前缀往往**嘈杂、冗余、甚至偏离正轨**。
- 此时简洁教师只能在已被污染的上下文上做局部修正，无法引导学生走向高效推理应避免的轨迹区域。
- 这造成一个**收敛前置瓶颈**：冷启动 OPSD 收敛到的压缩前沿（compression frontier）低于理论最优。

## 二、方法论：BIRD 两阶段自蒸馏

### 2.1 核心思想
BIRD（Bootstrapped Iterative Self-Reasoning Distillation）将同策略蒸馏分解为**离线自举** + **在线精炼**两个阶段，保持简洁自教师不变，但**重塑学生访问的前缀分布**。

### 2.2 分布匹配的形式化视角
将推理压缩视为分布匹配：

$$\min_{\theta} D(\pi_{\theta}, \pi_{\text{target}})$$

不同方法的核心差别不仅在于 $\pi_{\text{target}}$ 的构造，更在于**匹配损失在哪些前缀支撑上被施加**。

### 2.3 冷启动 OPSD 的目标函数

$$\mathcal{L}(\theta) = \mathbb{E}_{x \sim D, y \sim \pi_{\theta}(\cdot|x)} \left[ \sum_{t} D_{\text{KL}}\bigl(q_t \,\|\, p_t\bigr) \right]$$

其中：

- $q_t = \pi_{\theta}(\cdot \mid x, y_{<t})$：学生在原始提示 $x$ 下的分布；
- $p_t = \pi_{\bar{\theta}}(\cdot \mid x, c, y_{<t})$：教师（学生参数的 stop-gradient 副本）在简洁指令 $c$ 下的分布；
- 监督仅施加于**学生采样到的前缀** $y_{<t}$。

### 2.4 BIRD 两阶段流程

**Stage 1：静态自举（Static Bootstrap）**

对每个训练题 $x$，由基模型 $\pi_{\theta_0}$ 在简洁指令 $c$ 下采样一个 rollout $y$，仅当最终答案与 GT 匹配时保留：

$$D_{\text{filtered}} = \{(x, y) \mid \text{answer}(y) = \text{GT}(x)\}$$

然后进行**Prompt-Switch SFT**：轨迹在 $x + c$ 下生成，但 SFT 训练**使用原始提示 $x$**，使指令诱导的简洁性转化为**默认推理行为**而非推理时依赖。

$$\theta_{\text{SFT}} \leftarrow \text{LoRA-SFT}(\theta_0, D_{\text{filtered}};(x_i + c) \rightarrow x_i)$$

**Stage 2：动态精炼（Dynamic Refinement）**

从 $\theta_{\text{SFT}}$ 出发，使用标准 OPSD 目标（式 (3)），关键差异在于**初始化**：

- 教师参数 $\bar{\theta}$ 每 $M$ 步用 stop-gradient 从学生刷新一次；
- KL 仅在每个 rollout 的前 $T_{\text{KL}} = 1024$ 个 token 上计算；
- 轻量级设计：单次 rollout/题、$T_{\text{SFT}} = 2048$ token、1 epoch、**无外部教师模型**。

### 2.5 算法伪代码（Algorithm 1）
```
输入: 基模型 π_θ₀, 数据 D, 指令 c
输出: 压缩模型 π_θ∗

# Stage 1: 自举简洁前缀支撑
for (xᵢ, GTᵢ) ∈ D:
    采样 yᵢ ~ π_θ₀(·|xᵢ, c)
    if answer(yᵢ) == GTᵢ:
        截断 yᵢ 至 T_SFT
        加入 D_filtered
θ_SFT ← LoRA-SFT(θ₀, D_filtered)
θ ← θ_SFT

# Stage 2: 热启动同策略自蒸馏
for k = 1, 2, ..., K:
    每 M 步: θ̄ ← StopGrad(θ)
    采样批 B ⊂ D
    对每个 xᵢ ∈ B:
        采样 yᵢ ~ π_θ(·|xᵢ)
        计算 ℓᵢ,t = D_KL(π_θ(·|xᵢ, yᵢ,<t) ∥ π_θ̄(·|xᵢ, c, yᵢ,<t))
    更新 θ ← θ - ∇_θ L_B
θ∗ ← θ
```

| 主结果 | 3 模型 × 3 benchmark = 9 组 | Qwen3-1.7B/4B/8B 在 MATH-500、AIME 2024/2025 |
| 跨模型泛化 | 1 模型 × 3 benchmark | DeepSeek-R1-Distill-Llama-8B |
| 训练动力学 | 1 模型 × 1 benchmark | Qwen3-8B / MATH-500 上响应长度与 TE 随步数变化 |

### 5.2 充分性评价
**亮点**：
- 同时在**模型规模维度**（1.7B/4B/8B）与**模型家族维度**（Qwen3、Llama-based DeepSeek）评估，覆盖较广。
- 报告最佳 TE checkpoint 而非固定步数，避免对结果选择性报告的风险；提供训练动力学曲线佐证收敛行为。
- 消融涵盖了**组件必要性**与**顺序敏感性**，论证较完整。

**可改进处**：
- 仅与冷启动 OPSD（CRISP）充分对比，未与 RL 长度惩罚类方法（如 L1、Leash）或其他 SFT 压缩方法（TokenSkip、CoT-Valve）做直接对比。
- 评测集中在数学推理（domain 单一），未验证代码推理、逻辑推理等场景的泛化性。

---

## 六、主要结论与发现

1. **冷启动瓶颈存在**：冷启动 OPSD 收敛到一个较低的压缩前沿，长时间训练也无法追上热启动变体（TE 差距约 1.4 点，Qwen3-8B 上 CRISP ≈ 11.46–11.71 vs BIRD ≈ 13.02–13.11）。

2. **前缀支撑是 OPSD 的核心设计因素**：在哪种前缀分布上施加 KL 监督，与教师构造同样重要。

3. **指令诱导的简洁性是潜在线索**：仅推理时加简洁指令就能提升 TE，说明简洁行为已被基模型编码，BIRD 进一步将其转化为默认行为。

4. **规模效应**：模型越大，BIRD 增益越显著（1.7B 主要靠压缩，8B 同时提升准确率与效率）。

5. **泛化性**：在 DeepSeek-R1-Distill-Llama-8B（Llama 家族）上同样奏效，证明该方法不依赖于特定模型族。

6. **定量化结果示例（Qwen3-8B）**：
   - MATH-500：准确率 **86.2% → 92.0%**，长度 **3099 → 1115** tokens
   - AIME 2024：准确率 **38.33% → 58.33%**（+5 vs CRISP），长度减少 18%
   - AIME 2025：准确率 **26.25% → 42.08%**

---

## 七、优点与亮点

1. **问题识别新颖**：首次系统指出"前缀支撑"是 OPSD 的关键失败模式，并给出**支撑布局原则（support-placement principle）**这一清晰的设计指导。

2. **方法简洁且可移植**：
   - 无外部教师、不依赖大规模压缩语料；
   - Stage 1 仅 1 rollout/题 + 1 epoch SFT，开销极低；
   - Prompt-Switch 设计巧妙：让指令诱导的简洁性在推理时无需指令即可生效。

3. **互补性强**：SFT 提供**静态分布先行移动**，OPSD 提供**动态在策略精炼**，两阶段互补，SFT-only 与 CRISP 都明显弱于完整 BIRD。

4. **顺序敏感性论证充分**：OPSD→SFT 的反序实验显示准确率显著下降（特别是 AIME 2025 从 40.83% 跌到 28.33%），证明顺序设计非任意。

5. **跨模型、跨规模可复现**：在 Llama-based 模型上同样见效，方法具有较好鲁棒性。

6. **代码公开**：仓库地址 `https://github.com/KawhiC/BIRD` 便于复现。

---

## 八、不足与局限

1. **基线对比有限**：
   - 主要只比冷启动 OPSD（CRISP）一项蒸馏方法；
   - 未直接对比 RL 长度奖励类（L1、Leash）、其他 SFT 压缩方法（TokenSkip、V-Skip、CoT-Valve、CtrlCoT），难以判断其在压缩方法总体格局中的位置。

2. **任务域单一**：仅评测数学推理，**未涵盖代码生成、开放问答、多模态推理等场景**，对所提"prefix support"机制在其他长 CoT 任务上的可迁移性缺乏验证。

3. **没有更大模型的实验**：最大只到 8B；缺乏 70B 等更大规模上的可扩展性证据（即 prefix-support 是否仍是瓶颈）。

4. **超参数与工程细节披露不全**：
   - LoRA 的秩、$\alpha$、目标模块未详细给出；
   - 训练时间、总算力消耗未披露，难以判断方法性价比。

5. **依赖 GT 答案做筛选**：Stage 1 需要 ground-truth 来过滤正确轨迹，意味着该方法**仅适用有监督数据场景**，对开放式生成任务不友好。

6. **teacher 周期性更新间隔 $M$ 的影响、prompt $c$ 的具体内容与敏感性**未做消融，方法的稳定性边界尚不明晰。

7. **理论分析有限**：主要依赖实证，"前缀支撑决定 KL 效用"尚缺乏对 KL 分解或梯度分析层面的形式化论证。
