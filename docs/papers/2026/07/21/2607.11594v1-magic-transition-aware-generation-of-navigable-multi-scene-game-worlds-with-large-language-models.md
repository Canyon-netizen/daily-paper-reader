## 摘要
多场景导航（在一个有界空间内完成目标，然后穿越传送门进入下一个场景）是当代 3D 游戏的标志性特征，但其创作过程十分费力：每个传送门必须在两端具有一致的端点，每个内部空间在布置完毕后仍需保持可导航性，由此产生的连通性必须在许多文件中保持一致。最近的大语言模型（LLM）和多模态大语言模型（MLLM）场景生成器已经显著降低了单一室内场景的合成成本，但它们一次只能生成一个场景，无法通过简单的重复生成一个相互连通的多场景世界。我们识别出三个单场景方法未能解决的障碍：跨场景一致性、场景内可导航性，以及对过渡是否真正起作用的评估。我们提出了 MAGIC，一个提示到项目的系统，可同时解决这三个问题。MAGIC 是一个四阶段流水线，能将单一自然语言提示转化为可运行的多场景游戏项目：它规划一个共享的、过渡感知的中间表示，在通过洪泛填充验证器强制实现传送门可达性的同时具体指定每个场景，生成场景及其过渡脚本，并将它们合并为一个项目。由于现有的单场景保真度指标从不实际执行过渡，我们进一步引入了一个以过渡为中心的评估代理，在游戏中实际运行每个过渡。在一个包含 100 个多场景案例的新基准上，MAGIC 为每个案例都生成了可执行项目，并在端到端过渡识别上达到了 0.99 的精确率、0.95 的召回率和 0.96 的 F1 值；逐阶段来看，它比 LLM 基线和 Holodeck 恢复了更多的真实传送门，并产生了显著更可导航的布局。我们的代码可在 https://github.com/sereneee1201/MAGIC/ 获取。

## Abstract
Multi-scene navigation (clearing an objective in one bounded space and then crossing a portal into the next) is a defining feature of contemporary 3D games, but authoring it is laborious: every portal must have consistent endpoints on both sides, each interior must remain navigable once it is furnished, and the resulting connectivity must be kept consistent across many files. Recent large language model (LLM) and multimodal LLM (MLLM) scene generators have made single-interior synthesis dramatically cheaper, yet they produce one scene at a time and cannot, by naive repetition, yield a connected multi-scene world. We identify three obstacles that single-scene methods leave unsolved: cross-scene consistency, in-scene navigability, and the evaluation of whether a transition actually works. We present MAGIC, a prompt-to-project system that addresses all three. MAGIC is a four-stage pipeline that turns a single natural-language prompt into a runnable multi-scene game project: it plans a shared transition-aware intermediate representation, specifies each scene while enforcing portal reachability with a flood-fill validator, generates the scenes together with their transition scripts, and combines them into one project. Because existing single-scene fidelity metrics never execute a transition, we further introduce a transition-focused evaluation agent that runs each transition in play. On a new benchmark of 100 multi-scene cases, MAGIC produces an executable project for every case and reaches 0.99 precision, 0.95 recall, and 0.96 F1 on end-to-end transition identification; stage by stage, it recovers more ground-truth portals and yields markedly more navigable layouts than an LLM baseline and Holodeck. Our code is available at https://github.com/sereneee1201/MAGIC/.

## 1. 核心问题与研究动机

- **问题背景**：当代 3D 游戏（地牢探索、密室逃脱、RPG）的标志性特征是"多场景导航"——玩家在一个有界空间内完成目标后，通过传送门（门、楼梯、过场动画等）进入下一个场景。
- **手工创作痛点**：每个传送门必须在两端具有一致端点（位置、目的地、转场效果），每个室内场景在家具布置后仍需保持可导航性，连接图与跨文件的一致性需手动维护，被认为是 3D 游戏开发中最耗时的环节之一。
- **现有方法的局限**：Holodeck、Scenethesis 等 LLM/MLLM 场景生成器只能一次合成一个室内场景，简单重复无法产出连通的多场景世界。
- **三个未解决障碍（C1–C3）**：
  - **C1 跨场景一致性**：传送门是联合对象，状态无关的单场景提示会随上下文增大而丢失或幻觉跨场景引用。
  - **C2 场景内可导航性**：门道命名正确但家具可能物理性阻挡玩家，没有任何单场景指标能捕捉这种失败。
  - **C3 过渡评估缺失**：单场景保真度指标从不实际执行过渡，错连的传送门或断裂的过渡脚本对它们不可见。

## 2. 方法论

### 2.1 整体架构

MAGIC 是一个四阶段流水线，将单一自然语言提示转化为可运行的多场景 Unity 项目：

1. **规划阶段（Planning）**：从用户提示生成每个场景的描述与一个共享的"过渡感知中间表示（IR）"。
2. **场景规范阶段（Scene Specification）**：对每个场景分别展开，使用 2D 占据网格的洪泛填充（flood-fill）验证器强制保证传送门可达性。
3. **场景生成阶段（Scene Generation）**：生成网格资产并产出绑定到正确碰撞体的 LevelLoader 转场脚本。
4. **组合阶段（Combination）**：将各场景的 Unity 项目合并为单一项目，场景之间通过脚本相互引用。

### 2.2 关键技术与公式

**（1）过渡感知自动机（Transition-aware Automaton）**

$$A = (S, P, \delta, E)$$

其中 $S$ 为场景描述集合，$P$ 为传送门集合，$E$ 为转场效果集合，$\delta \subseteq S \times P \times E \times S$ 为过渡关系。$(s_i, p, e, s_j) \in \delta$ 表示传送门 $p$ 以效果 $e$ 连接 $s_i$ 与 $s_j$。由于传送门可双向穿越，$\delta$ 在场景端点上对称：

$$(s_i, p, e, s_j) \in \delta \Leftrightarrow (s_j, p, e, s_i) \in \delta$$

每个过渡作为无向、效果标记的边存储一次，下游阶段可查询与更新；图必须连通。当前可选效果为 `FadeInOut` 与 `IrisWipe`，由 LLM 根据相邻场景的风格差异自动选择。

**（2）2D 占据网格与洪泛填充验证**

将区域转换为 2D 占据网格：

$$G \in \{0, 1\}^{r \times c}, \quad r = \left\lceil \frac{\max_z - \min_z}{s} \right\rceil, \quad c = \left\lceil \frac{\max_x - \min_x}{s} \right\rceil$$

其中 $G_{ij}=1$ 表示可通行，$G_{ij}=0$ 表示障碍，单元格尺寸 $s=0.05$。除地毯（贴地）与吊挂于天花板的物体外，所有物体投影后占据的格子标记为阻塞。从传送门所在格子 $g_p$ 出发进行洪泛填充：

$$V_0 = \{g_p\}$$

$$V_{k+1} = V_k \cup \{(i', j') \in \mathrm{Adj}(i,j) : (i,j) \in V_k, G_{i'j'} = 1\}$$

$$V = \bigcup_{k=0}^{\infty} V_k$$

区域连通性定义为：

$$\mathrm{Connectivity} = \frac{|V|}{|\{(i,j): G_{ij}=1\}|}$$

若连通性等于 1，则所有传送门均可达；若小于 1，则存在部分或完全阻塞，触发对象放置的重生成过程，直到达到最大迭代次数并返回连通性最高的布局。

### 2.3 其他设计要点

- **分层对象注入**：先请求完整对象列表，再逐层填充所有对象的属性，确保全局兼容性与风格一致。
- **连接注入与移位算法**：LLM 初始放置常贴近墙面但不精确；算法计算与墙的最短距离，根据方向将连接向内平移半个厚度 $T$，使放置更逼真。
- **传送门识别**：通过 `isPortal` 标签跟踪对象型传送门；连通外部的门默认为传送门；带 `isPortal` 属性的窗户也视为传送门。缺失或多余的传送门数量反馈至 LLM 进行重新生成。
- **约束满足回路**：基于 Scenethesis 的 DSL 约束语言生成对象放置，验证模块比较输出与约束，列出违规项并迭代重新生成。
- **脚本生成**：通过模板填充而非让 LLM 直接生成脚本，确保可执行性。LevelLoader 绑定到传送门碰撞体（而非摄像机碰撞体）以保证触发灵敏度。

- **Stage 2（规范）**：MAGIC 召回率最高（0.9487），F1 接近 0.87，Precision（0.8333）略低于 LLM 基线（0.8825）但远高于 Holodeck（0.7350）；连通性 **0.9952**（近乎完美），占用率 0.2802（密度均衡），Holodeck 连通性仅 0.8545。
- **Stage 3（生成）**：MAGIC 在 100% 用例上产出可执行 Unity 项目，LevelLoader 数量与计划一致；LLM 基线 **0 个项目可执行**，且在近半数用例中生成多余 LevelLoader。
- **代理可靠性**：MAGIC 评估代理与人类判断的 MeanAbsDiff=0.0299（最小），优于 AB1（0.2187）与 AB2（0.0361），且每场景成本仅 40.70 秒。
- **可扩展性观察**：在 1–5 场景范围内，性能未随规模下降；论文未对更大规模做强扩展性声明。
- **失败模式**：Portal Match Rate 较低源于 MLLM 评判严格且物体网格数据集覆盖有限（例如"导引牌"被生成为普通板子）。

## 7. 优点

- **首次端到端多场景生成框架**：同时满足文本提示、3D 场景合成、跨场景过渡、可交互输出（Unity）四项能力，弥补现有方法空白（Table I）。
- **共享中间表示**：过渡感知自动机贯穿流水线，从根本上解决跨场景一致性问题（C1）。
- **物理可达性验证**：基于 2D 占据网格的洪泛填充直接量化玩家能否到达每个传送门，弥补单场景方法的盲点（C2）。
- **过渡评估范式**：首个在打包 Unity 项目中实际游玩、执行每个过渡并量化 Precision/Recall/F1/Approach Rate/Portal Match Rate 的评估代理（C3）。
- **首个多场景基准**：100 例覆盖场景图、循环/分支过渡、混合传送门类型，并提供真实跨场景过渡与可达性标注。
- **模板化脚本生成**：避免 LLM 直接生成 Unity 文件的不稳定性，保证 100% 可执行率。
- **鲁棒的设计选择**：LevelLoader 绑定到传送门而非摄像机、刚体附着所有对象、向内平移门道等细节提升真实可玩性。

## 8. 不足与局限

- **范围限制**：仅支持室内场景、Unity 引擎、英文提示、两种转场效果（FadeInOut / IrisWipe），尚未覆盖室外场景、其他引擎或多模态输入。
- **数据集依赖**：物体网格覆盖不足，导致部分传送门（如"导引牌"）被生成为语义不匹配的物体，影响 Portal Match Rate。
- **重生成机制**：对象放置达到最大重试次数时返回连通性最高的布局，仍可能存在少量阻塞。
- **评估代理可靠性有限**：仅 20 个用例、2 位人类标注者，统计力度不足。
- **随机性未充分处理**：每个用例仅一次运行，无方差或显著性检验，点估计可能偏乐观。
- **泛化性未验证**：基准仅来自两个数据集、一个引擎、一个模型族，未测试其他 LLM、其他引擎或大规模世界。
- **代理指标局限**：Approach Rate 与 Portal Match Rate 是真实玩家可达性的代理指标，可能未完全捕捉感知层面的过渡质量。
